# 性能剖析与调优

「我的页面卡」——这句话背后可能是完全不同的病：有人是 draw call 太多，有人是三角形爆炸，有人是填充率撑爆，还有人纯粹是阴影贴图开太大。**不先定位瓶颈就调优，等于没体检就吃药。**

这篇教你先用工具找出「到底卡在哪」，再对症下药。记住调优的黄金法则：**量一下 → 改一处 → 再量一下**。

::: tip 大白话时间
性能调优像**疏通堵车**。你得先看是「路口太多」（draw call）、「车太多」（三角形）、还是「路太窄」（填充率）。不同的堵法，疏通办法完全不同。瞎拓宽马路（乱优化）没用。
:::

## 一、三大瓶颈怎么判断

3D 渲染的性能瓶颈基本就三类，先用工具判断属于哪种：

| 瓶颈类型 | 典型症状 | 判断方法 | 主要解法 |
|---|---|---|---|
| Draw call 太多（CPU 瓶颈） | 帧率低，三角形数却不高 | `renderer.info.render.calls` > 1000~2000 | 合批：InstancedMesh / BatchedMesh / 合并几何体 |
| 三角形太多（GPU 顶点瓶颈） | 模型巨复杂，缩放窗口影响小 | `renderer.info.render.triangles` 数百万+ | 减面、LOD、视锥剔除 |
| 填充率爆了（GPU 像素瓶颈） | 分辨率越高越卡，窗口拉大就卡 | 降低 `setPixelRatio` 立刻变流畅 | 降分辨率、减少透明叠加、简化 shader |

::: tip 大白话时间
一个超简单的判断法：**把浏览器窗口拉大一倍**。如果立刻变卡，是填充率问题（像素太多）；如果没变化，多半是 draw call 或三角形问题。再配合 `renderer.info` 看具体数字。
:::

## 二、用工具量数据

### 2.1 renderer.info —— 内置计步器

```js
function logStats() {
  const r = renderer.info.render;
  const m = renderer.info.memory;
  console.table({
    'draw calls': r.calls,
    'triangles': r.triangles,
    'points': r.points,
    'lines': r.lines,
    'geometries': m.geometries,
    'textures': m.textures,
    'shader programs': renderer.info.programs?.length ?? 0,
  });
}
// 在循环里隔几秒打一次，看数值
```

### 2.2 stats.js —— 实时帧率面板

```js
import Stats from 'three/addons/libs/stats.module.js';

const stats = new Stats();
stats.showPanel(0); // 0=FPS, 1=帧时间(ms), 2=内存
document.body.appendChild(stats.dom);

renderer.setAnimationLoop(() => {
  stats.begin();
  // ...渲染...
  renderer.render(scene, camera);
  stats.end();
});
```

左上角会出现一个小面板，实时显示 FPS 和每帧耗时。

### 2.3 Spector.js —— 抓帧分析（终极武器）

Spector.js 是一个浏览器插件（支持 Chrome / Firefox），能**录制某一帧的每一个 WebGL 调用**：

1. 安装 Spector.js 插件并打开
2. 页面右上角点红色按钮开始录制
3. 触发一次渲染（点一下页面）
4. 停止录制，查看这一帧的所有 draw call、shader、纹理绑定、状态切换

| 看什么 | 说明 |
|---|---|
| Draw call 数量 | 和 renderer.info 对得上，逐条看每个调用 |
| 重复的状态切换 | 频繁切换材质/program 说明排序不好 |
| 过大的纹理上传 | 找有没有每帧重复上传纹理的代码 |
| Shader 编译 | 首帧卡通常是 shader 编译，之后会好 |

::: tip 大白话时间
`renderer.info` 告诉你**「有多少」**，Spector.js 告诉你**「每一次具体在干嘛」**。前者是统计报表，后者是逐帧监控录像。一般先用报表定位，再录像细看。
:::

## 三、Draw call 优化：合批三件套

### 3.1 InstancedMesh —— 画一堆一样的物体

适合：成百上千个**相同几何体 + 相同材质**的物体（草地、树林、子弹、星星）。

```js
const COUNT = 10000;
const geometry = new THREE.BoxGeometry(0.1, 0.1, 0.1);
const material = new THREE.MeshStandardMaterial({ color: 0x42b883 });
const mesh = new THREE.InstancedMesh(geometry, material, COUNT);

const dummy = new THREE.Object3D();
for (let i = 0; i < COUNT; i++) {
  dummy.position.set(
    (Math.random() - 0.5) * 100,
    (Math.random() - 0.5) * 100,
    (Math.random() - 0.5) * 100
  );
  dummy.rotation.set(Math.random() * Math.PI, Math.random() * Math.PI, 0);
  dummy.updateMatrix();
  mesh.setMatrixAt(i, dummy.matrix); // 设置每个实例的变换
}
mesh.instanceMatrix.needsUpdate = true;
scene.add(mesh);

// 10000 个方块，只有 1 个 draw call！
```

### 3.2 BatchedMesh —— 不同几何体也能合批

适合：几何体**不一样但材质相同**的一堆物体（r187 里已可用）。

```js
import * as THREE from 'three';

const MAX_INSTANCES = 1000;
const MAX_VERTICES = 100000;
const MAX_INDICES = 100000;

const batched = new THREE.BatchedMesh(MAX_INSTANCES, MAX_VERTICES, MAX_INDICES);

// 添加不同的几何体
const boxId = batched.addGeometry(new THREE.BoxGeometry(1, 1, 1));
const sphereId = batched.addGeometry(new THREE.SphereGeometry(0.5, 16, 16));

// 添加实例（指定用哪个几何体）
const id1 = batched.addInstance(boxId);
const id2 = batched.addInstance(sphereId);

// 设置每个实例的变换
const matrix = new THREE.Matrix4().makeTranslation(2, 0, 0);
batched.setMatrixAt(id1, matrix);

scene.add(batched);
// 不同形状合在一起，仍然只需很少的 draw call
```

### 3.3 合并几何体 —— 静态物体直接拼

```js
import { mergeGeometries } from 'three/addons/utils/BufferGeometryUtils.js';

const geos = [
  new THREE.BoxGeometry(1, 1, 1).translate(0, 0, 0),
  new THREE.BoxGeometry(1, 1, 1).translate(2, 0, 0),
  new THREE.BoxGeometry(1, 1, 1).translate(4, 0, 0),
];
const merged = mergeGeometries(geos);
const mesh = new THREE.Mesh(merged, material);
scene.add(mesh);
// 三个盒子合成一个几何体，1 个 draw call
// 适合不动的静态物体（地板、建筑）
```

| 方案 | 几何体 | 材质 | 能否单独控制每个 | 适用 |
|---|---|---|---|---|
| InstancedMesh | 相同 | 相同 | 能（变换/颜色） | 大量重复物体 |
| BatchedMesh | 可不同 | 相同 | 能 | 混合形状 |
| mergeGeometries | 合并成一个 | 可多材质 | 不能 | 纯静态场景 |

## 四、视锥剔除（Frustum Culling）

Three.js **默认开启**视锥剔除：不在相机视野里的物体自动不画。所以你通常不用管，但要知道几个坑：

```js
// 默认：每个 Mesh 自动做视锥剔除
mesh.frustumCulled = true; // 默认值

// 什么时候要关掉？
// 1. 顶点在 shader 里被移动（如大面积位移），包围盒不准 → 会误剔除
mesh.frustumCulled = false;

// 2. 自定义了 boundingSphere
geometry.computeBoundingSphere(); // 确保包围球准确
```

::: warning 注意
如果你在顶点着色器里大幅移动顶点，Three.js 用原始包围球判断，可能把「实际上应该可见」的物体剔掉——表现就是物体「突然消失」。这时设 `frustumCulled = false`，或手动算一个更大的包围球。
:::

## 五、LOD：远处用低模

```js
const lod = new THREE.LOD();

lod.addLevel(highDetailMesh, 0);    // 0~20 单位用高模
lod.addLevel(mediumDetailMesh, 20); // 20~50 单位用中模
lod.addLevel(lowDetailMesh, 50);    // 50 单位外用低模

scene.add(lod);
// LOD 每帧根据相机距离自动切换，Blender 里也能导出带 LOD 的 glTF
```

## 六、材质与光照成本

| 优化点 | 说明 | 做法 |
|---|---|---|
| 材质数量 | 每种材质 = 一次 shader program 切换 | 复用材质实例，别每个物体 new 一个 |
| 透明物体 | 透明无法深度写入，叠加多了很贵 | 减少大面积半透明层，用 alphaTest 替代 |
| PBR 材质 | `MeshStandardMaterial` 比 `Basic/Lambert` 贵 | 远景/次要物体用便宜材质 |
| 灯光数量 | 每个光源都增加 shader 计算 | 能合并就合并，移动端控制在 3~4 个灯 |
| 阴影 | 每个投影灯要额外渲染一遍场景 | 只让主光投影，次要光关掉阴影 |
| 后期处理 | 每个 pass 都要全屏绘制一遍 | 能不用就不用，合并 pass |

```js
// 用 alphaTest 代替透明（适合树叶、镂空贴图）
const mat = new THREE.MeshStandardMaterial({
  map: leafTexture,
  alphaTest: 0.5,        // 小于 0.5 的直接丢弃，不参与混合
  transparent: false,    // 不开透明，就能写深度、能被剔除
  side: THREE.DoubleSide,
});
```

## 七、阴影贴图优化

阴影是性能大户——每个投影灯都要把场景**再画一遍**。

| 参数 | 默认值 | 建议 | 作用 |
|---|---|---|---|
| `shadow.mapSize` | 512×512 | 1024 或 2048 | 分辨率，越大越清晰越贵 |
| `shadow.camera` 范围 | 较大 | 刚好包住场景 | 范围越小，阴影精度越高 |
| `shadow.bias` | 0 | -0.0005 左右 | 消除阴影表面条纹 |
| `shadow.normalBias` | 0 | 0.02 左右 | 消除斜坡上的阴影痤疮 |
| 投影灯数量 | — | 尽量 1 个 | 每多一个灯多渲染一遍 |

```js
renderer.shadowMap.enabled = true;
renderer.shadowMap.type = THREE.PCFShadowMap; // r187 推荐，别用废弃的 PCFSoftShadowMap

const light = new THREE.DirectionalLight(0xffffff, 3);
light.castShadow = true;
light.shadow.mapSize.set(2048, 2048);
light.shadow.camera.left = -10;
light.shadow.camera.right = 10;
light.shadow.camera.top = 10;
light.shadow.camera.bottom = -10;
light.shadow.camera.near = 0.5;
light.shadow.camera.far = 50;
light.shadow.bias = -0.0005;
light.shadow.normalBias = 0.02;
scene.add(light);
```

::: tip 大白话时间
阴影优化的核心就一句：**「范围收紧、分辨率够用就行」**。把阴影相机范围缩到刚好包住场景，2048 的贴图就能有很清晰的效果；范围放太大，再高的分辨率也是浪费。
:::

## 八、填充率与分辨率

```js
// 限制像素比，移动端尤其重要
// 不限制的话，Retina 屏 devicePixelRatio=3，像素数是 9 倍！
renderer.setPixelRatio(Math.min(window.devicePixelRatio, 2));

// 性能吃紧时可以动态降分辨率
let quality = 1.0;
renderer.setPixelRatio(Math.min(window.devicePixelRatio, 2) * quality);
// 检测到掉帧时 quality *= 0.8，流畅了再慢慢加回来
```

## 九、性能预算表

给自己定个「预算」，超了就优化。以下是常见目标（以 60 FPS 为目标）：

| 指标 | 移动端预算 | 桌面端预算 | 超标怎么办 |
|---|---|---|---|
| Draw calls | < 200 | < 1000 | InstancedMesh / 合并 / BatchedMesh |
| 三角形数 | < 10 万 | < 100 万 | 减面、LOD、剔除 |
| 纹理数量 | < 30 | < 100 | 图集、KTX2 压缩、复用 |
| 纹理单张尺寸 | ≤ 1024 | ≤ 2048 | 缩小、mipmap |
| 动态灯光 | ≤ 3 | ≤ 8 | 合并灯、烘焙光照 |
| 投影灯 | 1 | 1~2 | 只让主光投影 |
| 像素比 | ≤ 2 | ≤ 2 | 限制 devicePixelRatio |
| 后期 pass | ≤ 2 | ≤ 4 | 合并、去掉不必要效果 |
| 首屏加载 | < 3 s | < 5 s | Draco/KTX2、懒加载 |
| 帧时间 | < 16.7 ms | < 16.7 ms | 按上面瓶颈分类处理 |

## 十、调优流程总结

1. **量**：打开 stats.js，看 FPS；打印 `renderer.info`，看 draw call 和三角形数
2. **判断**：拉大窗口测填充率；对照预算表找超标项
3. **定位**：需要细看时上 Spector.js 抓一帧
4. **改一处**：一次只改一个优化点
5. **再量**：确认改进了，且没引入新问题（比如物体消失 = 剔除误伤）
6. **重复**：直到达标

::: tip 大白话时间
调优不是一次性的事，是**循环**：量 → 改 → 量。最忌讳的就是「我感觉这样会快」然后一口气改十个地方——最后不知道哪个有用，甚至可能改坏了都不知道。慢慢来，一次改一个。
:::
