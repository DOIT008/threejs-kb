# 内存管理与泄漏排查

写 Demo 时你怎么造都行，页面关掉就没了。但做**要上线的项目**——尤其是 SPA 里来回切页面、反复创建销毁场景——内存泄漏就是定时炸弹：用户逛一圈回来，页面越来越卡，最后标签页直接崩掉。

Three.js 的内存管理有个反直觉的点：**JS 对象会被垃圾回收，但 GPU 资源不会自动释放**。你在 JS 里 `geometry = null` 没用，显卡里的那份数据还在。必须手动 `dispose()`。

::: tip 大白话时间
把 GPU 显存想象成**租用的仓库**。JS 里的变量是「提货单」，垃圾回收只回收提货单，不会自动退还仓库里的货。你必须主动打电话（`dispose()`）说「这些货我不要了，退租」——否则仓库一直被占着，越堆越满。
:::

## 一、哪些东西需要手动 dispose

| 资源类型 | 例子 | 不 dispose 的后果 | 怎么释放 |
|---|---|---|---|
| 几何体 Geometry | `BoxGeometry`、`BufferGeometry` | 顶点数据一直占显存 | `geometry.dispose()` |
| 材质 Material | `MeshStandardMaterial` 等 | shader、uniform 占显存 | `material.dispose()` |
| 纹理 Texture | 图片、`DataTexture` | 图片占显存（很占！） | `texture.dispose()` |
| 渲染目标 RenderTarget | `WebGLRenderTarget` | 离屏缓冲占显存 | `renderTarget.dispose()` |
| 渲染器 Renderer | `WebGLRenderer` | WebGL 上下文、内部缓存不释放 | `renderer.dispose()` + `renderer.forceContextLoss()` |
| 控制器 Controls | `OrbitControls` | 事件监听没摘，回调还在跑 | `controls.dispose()` |
| 后期处理 Composer | `EffectComposer` | 内部的 render target 不释放 | `composer.dispose()` |
| 事件监听 | `resize`、鼠标事件 | 回调持有场景引用，泄漏整条链 | `removeEventListener()` |

::: warning 注意
`scene.remove(mesh)` **不等于**释放资源！它只是把物体从场景里摘掉，几何体、材质、纹理还赖在显存里。必须对每个资源调用 `dispose()`。
:::

## 二、用 renderer.info 监控

Three.js 自带一个「计步器」`renderer.info`，能实时看有多少资源活着：

```js
console.log(renderer.info);

// 常用字段：
// renderer.info.memory.geometries  当前存活的几何体数量
// renderer.info.memory.textures    当前存活的纹理数量
// renderer.info.render.calls       本帧 draw call 数
// renderer.info.render.triangles   本帧三角形数
// renderer.info.programs.length    编译过的 shader 程序数
```

一个最简单的泄漏检测法：**反复进入/退出场景，打印 `renderer.info.memory`，看数字是不是一直涨**。

```js
function logMemory(label) {
  const { geometries, textures } = renderer.info.memory;
  const programs = renderer.info.programs?.length ?? 0;
  console.log(`[${label}] geometries=${geometries} textures=${textures} programs=${programs}`);
}

// 进场景前打一次，销毁后再打一次
logMemory('进入前');
disposeScene(scene, renderer);
logMemory('销毁后'); // 数字应该回到基线，而不是继续涨
```

::: tip 大白话时间
`renderer.info.memory` 就是你的**体重秤**。切场景前后各称一次：数字回到原来的值，说明瘦回去了（没泄漏）；数字一路涨，说明「只增不减」，肯定哪里没 dispose。
:::

## 三、完整的 disposeScene 工具函数

下面这个函数是生产项目里可以直接用的版本。它递归遍历整个场景树，把几何体、材质、材质上的所有纹理、骨骼、都释放掉，并清理控制器、事件监听和渲染器。

```js
import * as THREE from 'three';

/**
 * 彻底销毁一个场景及其所有 GPU 资源
 * @param {THREE.Scene} scene 要销毁的场景
 * @param {THREE.WebGLRenderer} renderer 渲染器
 * @param {object} [options] 额外要清理的东西
 */
function disposeScene(scene, renderer, options = {}) {
  if (!scene) return;

  // 1. 停止动画循环（r187 推荐写法：传 null 即停止）
  renderer.setAnimationLoop(null);

  // 2. 清理额外对象：控制器、composer、定时器等
  const { controls, composer, timers = [] } = options;
  controls?.dispose();
  composer?.dispose();
  timers.forEach((t) => clearInterval(t));

  // 3. 摘掉外部事件监听（传进来的 [target, type, handler] 数组）
  (options.listeners || []).forEach(({ target, type, handler }) => {
    target.removeEventListener(type, handler);
  });

  // 4. 递归释放材质上挂的所有纹理
  //    材质里可能有很多贴图槽位：map、normalMap、alphaMap、envMap……
  function disposeMaterial(material) {
    for (const key of Object.keys(material)) {
      const value = material[key];
      if (value && value.isTexture) {
        value.dispose();
      }
    }
    material.dispose();
  }

  // 5. 递归遍历场景树
  scene.traverse((object) => {
    // 几何体
    if (object.geometry) {
      object.geometry.dispose();
    }

    // 材质（可能是单个，也可能是数组）
    if (object.material) {
      const materials = Array.isArray(object.material)
        ? object.material
        : [object.material];
      materials.forEach(disposeMaterial);
    }

    // SkinnedMesh 的骨骼纹理
    if (object.isSkinnedMesh) {
      object.skeleton?.dispose();
    }
  });

  // 6. 清空场景，移除所有子节点
  scene.clear();

  // 7. 释放 render target（如果外面传进来了）
  (options.renderTargets || []).forEach((rt) => rt.dispose());

  // 8. 释放渲染器，主动丢失 WebGL 上下文
  renderer.dispose();
  renderer.forceContextLoss();
  renderer.domElement.remove(); // 从 DOM 上摘掉 canvas
}

// 9. 外部调用方自己断开引用（前提：scene / renderer 用 let 声明）
// 注意：在函数内部写 scene = null 只改了形参的局部副本，对调用方毫无作用
disposeScene(scene, renderer);
scene = null;
renderer = null;
```

::: danger 警告
**共享资源要小心。** 如果多个 Mesh 共用同一个 geometry 或 material，`traverse` 会重复 dispose 它。虽然 Three.js 对重复 dispose 做了容错，但更稳妥的做法是先用 `Set` 去重：

```js
const geos = new Set();
const mats = new Set();
const texs = new Set();

scene.traverse((obj) => {
  if (obj.geometry) geos.add(obj.geometry);
  if (obj.material) {
    (Array.isArray(obj.material) ? obj.material : [obj.material]).forEach((m) => mats.add(m));
  }
});

texs.forEach((t) => t.dispose());
mats.forEach((m) => m.dispose());
geos.forEach((g) => g.dispose());
scene.clear();
```
:::

## 四、SPA 路由切换的清理

在 Vue / React 里，路由切换时组件会卸载。清理逻辑必须放在**卸载钩子**里：

```js
// Vue3 示例（Composition API）
import { onMounted, onBeforeUnmount, ref } from 'vue';
import * as THREE from 'three';

const container = ref(null);
let scene, camera, renderer, controls, resizeHandler;

onMounted(() => {
  scene = new THREE.Scene();
  camera = new THREE.PerspectiveCamera(75, 1, 0.1, 1000);
  renderer = new THREE.WebGLRenderer({ antialias: true });
  container.value.appendChild(renderer.domElement);

  resizeHandler = () => {
    const w = container.value.clientWidth;
    const h = container.value.clientHeight;
    camera.aspect = w / h;
    camera.updateProjectionMatrix();
    renderer.setSize(w, h);
  };
  window.addEventListener('resize', resizeHandler);

  renderer.setAnimationLoop(() => {
    controls?.update();
    renderer.render(scene, camera);
  });
});

onBeforeUnmount(() => {
  // 关键：把事件监听和控制器传给 disposeScene 一起清理
  disposeScene(scene, renderer, {
    controls,
    listeners: [{ target: window, type: 'resize', handler: resizeHandler }],
  });
});
```

```js
// React 示例（useEffect）
useEffect(() => {
  // ...创建场景...
  return () => {
    // cleanup 函数，组件卸载时执行
    disposeScene(scene, renderer, {
      controls,
      listeners: [{ target: window, type: 'resize', handler: resizeHandler }],
    });
  };
}, []);
```

::: warning 注意
React 18 的 StrictMode 会在开发环境**故意挂载两次**（mount → unmount → mount）来暴露副作用问题。如果 cleanup 写错了，你会看到「画布出现又消失」「WebGL context lost」。这其实是好事——它帮你提前发现泄漏。确保 cleanup 彻底，就不会有问题。
:::

## 五、常见泄漏模式

| 泄漏模式 | 症状 | 解法 |
|---|---|---|
| 只 `scene.remove()` 不 `dispose()` | 切场景后显存不降 | 对每个 geometry/material/texture 调 dispose |
| 纹理重复创建 | 每次进页面 `new TextureLoader().load()` | 用全局缓存复用纹理，只 dispose 一次 |
| 事件监听没摘 | resize 回调还在跑，持有旧场景 | 卸载时 `removeEventListener` |
| 动画循环没停 | 组件卸载后还在渲染旧场景 | `setAnimationLoop(null)` |
| 共享资源被某个场景 dispose 了 | 其他场景突然变黑/没纹理 | 用引用计数，谁最后用谁释放 |
| 定时器 / requestAnimationFrame 泄漏 | 定时器一直跑 | 保存 id，`clearInterval` / `cancelAnimationFrame` |
| 闭包持有整个场景 | 页面卸载了但内存不降 | 及时把大对象引用置 null |

## 六、检测工具

| 工具 | 能干嘛 | 怎么用 |
|---|---|---|
| `renderer.info.memory` | 快速看几何体/纹理数量 | 代码里直接打印，切场景前后对比 |
| Chrome Memory 面板 | 拍堆快照，看对象保留链 | DevTools → Memory → Take snapshot，操作前后各拍一张对比 |
| Chrome Performance 面板 | 看内存曲线是否持续上涨 | DevTools → Performance → 勾选 Memory，录制一段操作 |
| three.js devtools | 可视化看场景树、材质、几何体、资源 | 浏览器插件，实时检查场景里到底有哪些东西 |
| Spector.js | 抓每帧 WebGL 调用，看资源上传 | 浏览器插件，定位意外的重复上传 |

::: tip 大白话时间
查泄漏的核心方法就一句话：**「反复做同一件事，看内存是不是只涨不降」**。进页面 → 出页面 → 进页面 → 出页面……重复十次，如果内存阶梯式上涨从不回落，那一定有东西没释放。
:::

## 七、场景销毁检查清单

每次写一个会反复创建/销毁的场景，销毁逻辑写完后来对一遍：

- [ ] 调用了 `renderer.setAnimationLoop(null)` 停止渲染循环
- [ ] 遍历场景，对所有 `geometry` 调用了 `dispose()`
- [ ] 对所有 `material`（含数组）调用了 `dispose()`
- [ ] 对材质上所有纹理槽位（`map`、`normalMap`、`envMap`…）调用了 `dispose()`
- [ ] 对 `SkinnedMesh` 的 `skeleton` 调用了 `dispose()`
- [ ] 对 `EffectComposer`、`WebGLRenderTarget` 调用了 `dispose()`
- [ ] 对 `OrbitControls` 等控制器调用了 `dispose()`
- [ ] 所有 `addEventListener` 都配对了 `removeEventListener`
- [ ] 所有 `setInterval` / `setTimeout` 都 clear 了
- [ ] 调用了 `renderer.dispose()` 和 `renderer.forceContextLoss()`
- [ ] 从 DOM 移除了 `renderer.domElement`
- [ ] 把 scene / camera / renderer 等大对象引用置 null
- [ ] 用 `renderer.info.memory` 验证：销毁后数字回到基线

::: tip 大白话时间
内存管理不难，难的是**养成习惯**。把上面这份清单贴在显示器旁边，每次写清理代码照着勾一遍，几个月后你就会下意识地做对——就像系安全带一样自然。
:::
