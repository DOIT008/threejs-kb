::: tip 最有效的学法

官方示例的源码是免费的最好的老师。遇到酷炫效果，先去 examples 里搜关键词，八成能找到现成的。
:::

### 深一层：官方示例到底该怎么「抄」

「多看官方示例」是正确的废话。真正有效的是**带着问题拆示例**，按下面四遍读：

| 遍数 | 只看什么 | 要回答的问题 |
| --- | --- | --- |
| 第 1 遍 | 页面效果 | 这个效果由哪几个视觉元素组成？ |
| 第 2 遍 | `init()` / 变量声明 | 它创建了哪些 Three.js 对象？分别属于「三件套/资源/交互」哪一类？ |
| 第 3 遍 | `animate()` / `onFrame()` | 每帧改了什么？为什么必须用 `delta` 而不是固定步长？ |
| 第 4 遍 | 删代码 | 注释掉一段，看画面少什么——这是理解一段代码作用最快的办法 |

::: tip 大白话时间
读示例就像**拆玩具**：第一遍看它长什么样，第二遍拧螺丝拆开，第三遍看齿轮怎么转，第四遍故意装错一个零件看会怎样。

只「看」不拆，你记住的是「这个效果叫 bloom」；拆过一遍，你记住的是「bloom = 渲染到 RenderTarget + 阈值提取 + 模糊 + 合成」。
:::

**官方源码的阅读顺序（别从 WebGLRenderer 开始）：**

```txt
① src/core/Object3D.js          ← 一切物体的基类，看懂 add/remove/traverse
② src/cameras/PerspectiveCamera.js ← camera 到底怎么算出投影
③ src/geometries/BufferGeometry.js ← attributes 存的是什么
④ src/materials/Material.js      ← 材质基类与 needsUpdate
⑤ src/renderers/WebGLRenderer.js ← 最后再看，前面都懂了才啃得动
```

前 4 个文件每个几百行，一晚上能读完；`WebGLRenderer.js` 几千行，永远读不完——**带着具体问题去查**（比如「draw call 在哪统计的」），而不是通读。

## 四、框架集成

| 框架 | 库 | 适合 |
|---|---|---|
| React | React Three Fiber（@react-three/fiber） | React 项目 |
| Vue | TresJS（@tresjs/core） | Vue 项目 |
| Svelte | Threlte | Svelte 项目 |
| 原生 | Three.js 本身 | 任何项目 |

::: tip 大白话时间
这些库本质上是把 Three.js 的命令式 API 包装成各自框架的「组件式」写法。

比如原生写 `scene.add(mesh)`，在 Vue 里就写成 `<TresMesh />` 标签。**底层还是 Three.js**——所以先把原生学明白，用框架只是换种写法而已。
:::

### 深一层：按目标选路线，别按兴趣乱逛

「进阶路线」人人都写同一套，但不同目标该花的时间完全不同。按你的实际目标挑一条：

| 目标 | 重点投入 | 可以跳过 | 验收作品 |
| --- | --- | --- | --- |
| 产品展示页 | 模型加载、环境贴图、Bloom、响应式 | 着色器、WebGPU | 一个能 360° 看、能换配置的商品页 |
| 数据可视化 | BufferGeometry、InstancedMesh、拾取、文字标签 | PBR 材质细节 | 一张能点、能筛的 3D 数据地图 |
| 网页小游戏 | 动画循环、碰撞检测、控制器、状态机 | glTF 优化管线 | 一个能玩通的小游戏 |
| 数字孪生 | 实时数据驱动、状态机、Pinia、性能优化、内存管理 | GLSL 底层 | 一个带实时看板和报警的工厂场景 |
| 底层/技术美术 | GLSL、PBR 数学、Node Material、渲染管线 | 业务框架集成 | 一个自定义 ShaderMaterial 效果集 |

**30 天精进节奏（以「产品展示页」为例）：**

| 周 | 主题 | 每天做什么 | 周末交付 |
| --- | --- | --- | --- |
| 第 1 周 | 抄 10 个官方示例 | 每天拆 1 个，写 3 行笔记记录「哪行改了会怎样」 | 自己的示例拆解笔记 |
| 第 2 周 | 做减法 | 把第 17 章实战项目删到只剩核心，再自己加回来 | 一个不依赖教程的场景骨架 |
| 第 3 周 | 换真实素材 | 找/做一个 GLB，处理单位、贴图、动画 | 模型正常显示的产品页 |
| 第 4 周 | 打磨与上线 | 加环境贴图、Bloom、加载进度、移动端适配、构建部署 | 一个能发给别人看的链接 |

::: warning 最容易被忽略的一步
第 2 周的「做减法」是进步最快的环节。**能从别人的代码里删掉 80% 还跑得起来**，说明你真的懂了剩下 20% 在干什么。
:::

## 五、能力自测：18 道题定位你的真实水平

别凭感觉判断自己"学完了"。下面每题答不出来，就回去补对应章节。

**🟢 L1 · 能认出来（基础）**

1. 场景、相机、渲染器各自负责什么？
2. `Mesh` 和 `Geometry` / `Material` 是什么关系？
3. Three.js 的 Y 轴朝哪个方向？右手坐标系怎么比划？
4. `position` / `rotation` / `scale` 分别改什么？

**🔵 L2 · 能写出来（用法）**

5. 怎么让一个立方体投出影子？说出至少 3 个必要条件。
6. `renderer.setAnimationLoop()` 里为什么要传 `delta`？
7. 射线拾取时，鼠标坐标为什么要除以窗口宽高再乘 2 减 1？
8. 颜色贴图和数据贴图的 `colorSpace` 分别怎么设？
9. `loadAsync()` 比 `load()` 好在哪？什么时候必须用 `await`？

**🟠 L3 · 能解释（原理）**

10. 为什么运行时改了顶点数据要同时调 `needsUpdate` 和 `computeVertexNormals()`？
11. `InstancedMesh` 为什么能把一万次 draw call 变成一次？
12. 开了 `enableDamping` 后，为什么必须每帧调 `update()`？
13. `onBeforeCompile` 里为什么必须设置 `customProgramCacheKey()`？
14. 用 `EffectComposer` 后颜色发灰，最可能是漏了什么？

**🔴 L4 · 能扛事（生产）**

15. 页面越切越卡，怎么用 `renderer.info` 验证是不是内存泄漏？
16. 粒子系统「转个头就消失」，有哪三种解法？
17. Vue3 里为什么要用 `shallowRef` / `markRaw` 包 Three.js 对象？
18. GLB 加载失败时，怎么做兜底才不让用户看到空白？

::: tip 自测结果怎么用
- 1~4 答不出 → 回「基础入门」重来，别硬啃进阶
- 5~9 答不出 → 回「核心概念 / 动画与交互」，这是地基
- 10~14 答不出 → 你处于「会抄不会改」阶段，重点读各章「深一层」
- 15~18 答不出 → 还没法独立上线项目，重点读生产级专题

**答案全在本知识库里**，用目录搜索关键词就能定位——「能查到」本身就是能力。
:::

## 六、r187 时代的新方向

::: tip 值得关注
- **WebGPURenderer**：已相对成熟，自动回退 WebGL 2，新项目可以考虑
- **Node Material / TSL**：用 JS 拼装着色器，替代手写 GLSL；r187 里 TSL 会自动把运算参数提升到共同类型，写起来更省心
- **GSplat（高斯泼溅）**：r186 新增 addon，做真实场景扫描重建
- **SunLight**：r186 新增，级联阴影，大场景户外光照更真实
- **r187 本版变化**：PMREM 环境贴图改用立方体渲染目标重建，IBL 照明质量更高；`MeshPhysicalMaterial` 加入 EON 粗糙漫反射 BRDF；新增 `Texture.mipmapsAutoUpdate` 和 WebGPU 深度-only 渲染目标；移除了 `CubeUVReflectionMapping`
:::

## 结语

::: tip 大白话时间
3D 这东西，**看着难，动手就那么回事**。

你现在已经掌握了最核心的那套东西：场景、相机、渲染器、网格、光照、动画循环。剩下的就是不停地写、不停地改、不停地看效果。

别怕写烂代码——第一个 3D 页面谁不是从「一片黑」开始的。去造点好玩的吧。🚀
:::
