# 常见问题排错

收集那些「明明写对了却跑不起来」的经典问题。

## 〇、先别猜：四步定位到哪一层

新手排错最大的浪费，是**看到黑屏就开始从头逐行读代码**。正确做法是先花 30 秒判断「坏在哪一层」，再进具体章节找答案。

```txt
第 1 步：控制台有红字吗？
   ├─ 有 → 90% 是代码/资源问题 → 直接看第 6、7、11、12 节
   └─ 没有 → 进第 2 步

第 2 步：canvas 在 DOM 里、且尺寸不为 0 吗？
   ├─ 不在/为 0 → CSS 或 appendChild 问题 → 看第 2、3 节
   └─ 正常 → 进第 3 步

第 3 步：把材质换成纯红 MeshBasicMaterial 后能看见吗？
   ├─ 能看见 → 几何体、相机都没问题 → 是光照/材质 → 看第 1、9 节
   └─ 看不见 → 相机或变换问题 → 看第 1、8 节

第 4 步：物体在动吗？render 被调用了吗？
   ├─ 渲染统计里 calls > 0 → 渲染在跑，只是结果不对 → 精查材质/色彩/后期
   └─ calls = 0 → 场景里根本没东西 → 检查 add() 和动画循环
```

::: tip 大白话时间
这套流程的核心是**每次只砍掉一半可能性**，跟猜数字游戏一样。

别小看「换成纯红材质」这一招——它一次就把「相机/物体/渲染流程」和「光照/材质」这两大类问题分开了。5 秒钟能做完，比盯着 200 行代码找半小时强。
:::

**第 4 步要会看渲染统计：**

```js
console.log('draw calls:', renderer.info.render.calls);
console.log('triangles:', renderer.info.render.triangles);
console.log('geometries:', renderer.info.memory.geometries);
```

| 读数 | 说明什么 |
| --- | --- |
| `calls = 0` | 什么都没画：场景空、物体在视锥外、或者根本没调 `render()` |
| `calls > 0` 但画面黑 | 画了但结果是黑的：光照、材质、色彩管理、后期通道 |
| `calls` 几千上万 | 性能问题：该合批了（第 10 节） |
| `geometries` 只增不减 | 内存泄漏：忘了 `dispose()` |

**最小可复现模板**（遇到问题先把代码砍成这样，再一块块加回来）：

```js
import * as THREE from 'three';

const scene = new THREE.Scene();
scene.background = new THREE.Color(0x222222);

const camera = new THREE.PerspectiveCamera(60, innerWidth / innerHeight, 0.1, 100);
camera.position.set(0, 0, 5);
camera.lookAt(0, 0, 0);

const renderer = new THREE.WebGLRenderer();
renderer.setSize(innerWidth, innerHeight);
document.body.appendChild(renderer.domElement);

// 只放一个不受光照影响的红方块
scene.add(new THREE.Mesh(
  new THREE.BoxGeometry(),
  new THREE.MeshBasicMaterial({ color: 0xff0000 })
));

renderer.render(scene, camera); // 先只渲染一帧，排除动画循环的干扰
```

这段代码能显示红方块 → 环境和渲染管线是好的，问题一定在你后来加的东西里。这段代码也黑 → 问题在浏览器/WebGL 层面（显卡驱动、硬件加速被关）。

## 1. 画面一片黑

按顺序检查：

1. **控制台有报错吗？** F12 打开开发者工具，红色报错优先解决
2. **材质是不吃光的吗？** `MeshStandardMaterial` 没加灯就是黑的，先加 `HemisphereLight`
3. **物体在相机背后吗？** 检查 `camera.position` 和 `mesh.position`，相机默认朝 -Z 看
4. **物体太小/太远吗？** `camera.position.z = 5` 配 1 单位立方体正合适
5. **`far` 裁掉了吗？** 物体在 200 单位外但 `far=100`，当然看不见
6. **画布加到页面了吗？** 检查有没有 `document.body.appendChild(renderer.domElement)`
7. **动画循环调用了吗？** 只 `renderer.render()` 一次，物体不会动但至少该看见

::: tip 调试大招
把材质临时换成：

```js
new THREE.MeshBasicMaterial({ color: 0xff0000, wireframe: true })
```

纯红 + 线框 + 不吃光。能看见红色线框 → 物体位置没问题，问题在光照或材质；看不见 → 问题在相机或渲染流程。
:::

## 2. 页面出现滚动条

```css
body { margin: 0; overflow: hidden; }
canvas { display: block; }
```

`canvas` 默认是行内元素，底部会有几像素空隙，`display: block` 能消掉。

## 3. 窗口缩放后画面变形

漏了 resize 处理（改相机参数后必须 `updateProjectionMatrix()`）：

```js
addEventListener('resize', () => {
  camera.aspect = innerWidth / innerHeight;
  camera.updateProjectionMatrix(); // 别忘！
  renderer.setSize(innerWidth, innerHeight);
});
```

## 4. 物体表面一闪一闪（z-fighting）

两个面**紧贴在一起**，显卡不知道该画谁。

::: tip 大白话时间
就像把两张纸完全叠在一起，从侧面看边缘会「打架」。

**解决**：稍微错开一点距离（比如 `z: 0.001`），或者调整相机的 `near`（别设成 0.00001 这种极小值），或者设 `polygonOffset`。
:::

```js
material.polygonOffset = true;
material.polygonOffsetFactor = -1;
```

## 5. 阴影有条纹（Shadow Acne）

```js
sun.shadow.bias = -0.0001;
sun.shadow.normalBias = 0.02; // 更推荐
```

::: warning 注意
bias 别设太大，否则影子会和物体「脱节」（叫 peter panning，像皮特潘的影子跑了）。慢慢微调，从 `-0.0001` 开始试。
:::

## 6. 直接双击 HTML 打不开

`type="module"` 在 `file://` 协议下会被浏览器拦。用 VS Code 的 Live Server，或执行 `npx serve` / `python -m http.server`。

## 7. 版本 API 对不上

你可能在看老教程。常见变更：

| 老写法 | 新写法（r187） | 变更版本 |
|---|---|---|
| `THREE.Geometry` | `BufferGeometry` | r125 移除 |
| `outputEncoding` | `outputColorSpace` | r152 |
| `new THREE.Clock()` | `new THREE.Timer()` | r183 废弃 |
| `PCFSoftShadowMap` | `PCFShadowMap` | r182 起废弃，r186 起移除 |
| `encoding` on texture | `colorSpace` | r152 |

## 8. 旋转方向看着不对

Three.js 的旋转用**弧度**不是角度。

```js
mesh.rotation.y = Math.PI / 2;  // ✅ 90 度
mesh.rotation.y = 90;           // ❌ 转了 90 弧度
```

## 9. 改了材质颜色没反应

- 材质用了 `map` 贴图？贴图颜色会**乘以** `color`，色相会被染色。想要原色把 color 设为白色
- 共享材质？改一个全变（第 5 章讲过），用 `clone()`
- 忘了 `material.needsUpdate = true`？改贴图或某些属性后需要它

## 10. 性能越来越卡

- 在动画循环里 `new` 对象了？检查并移到外面
- 模型没做 LOD 或 InstancedMesh？
- 阴影/后期处理开太多？
- 切换场景后没 `dispose()`？

## 11. 纹理加载失败（CORS）

浏览器控制台报 `CORS policy` 错误：

- 图片服务器没开放跨域 → 换成本地图片
- 用图床 → 确认支持跨域
- `loader.setCrossOrigin('anonymous')` 有时能解决

## 12. 找不到某个 addon 模块

检查导入路径是不是 `three/addons/...`：

```js
// ✅ 正确
import { OrbitControls } from 'three/addons/controls/OrbitControls.js';

// ❌ 错误
import { OrbitControls } from 'three/examples/jsm/controls/OrbitControls.js';
```

用 importmap 时必须配好 `three/addons/` 的映射（第 2 章有）。

::: tip 最后的建议
遇到问题时，**先把代码简化到最小可复现**——只留一个立方体、一盏灯。能跑通再一块块加回去，问题自然定位。

另外，搜索引擎搜英文关键词（"three.js black screen"、"three.js shadow acne"）通常比中文结果更靠谱，因为英文社区讨论量大得多。
:::

## 13. 控制台报错怎么读

着色器、资源加载这类错误**不会抛 JS 异常**，只会在控制台里留一行红字。按关键词对号入座：

| 控制台关键词 | 属于哪一层 | 去哪节 |
| --- | --- | --- |
| `Failed to resolve module specifier` | importmap / 路径 | 第 12 节、第 7 节 |
| `CORS policy` | 资源跨域 | 第 11 节 |
| `404 (Not Found)` | 路径写错 / 外部资源缺失 | 第 11 节 + Network 面板 |
| `THREE.WebGLRenderer: Context Lost` | 显存爆了 / 上下文丢失 | 第 10 节 |
| `GL_INVALID_OPERATION` | 着色器编译或状态错误 | 着色器入门的 GLSL 报错表 |
| `Cannot read properties of undefined` | 加载还没完成就用了返回值 | `await loadAsync()` 后再用 |
| `is not a constructor` | 版本 API 对不上 | 第 7 节 |
| `THREE.Object3D.add: object not an instance` | 传进去的不是 Object3D（常见于 Vue 响应式代理） | 用 `markRaw` 包住 |

::: warning 别忽略警告
`THREE.WebGLProgram: Shader Error` 是**警告色（黄）**而不是红字，但它意味着着色器根本没编译成功——物体会显示成洋红色或干脆消失。看到就当错误处理。
:::

## 14. 排查顺序有讲究：先外部后内部

一个经验法则：**越靠外的原因越常见，也越好查**。

| 优先级 | 层面 | 典型原因 |
| --- | --- | --- |
| 1 | 环境 | `file://` 协议、端口没开、依赖没装 |
| 2 | 资源 | 路径 404、CORS、图片格式不对 |
| 3 | 场景 | 物体没 add、位置在视锥外、near/far 不对 |
| 4 | 渲染 | 灯光、材质、色彩管理、后期通道顺序 |
| 5 | 逻辑 | 动画循环、事件监听、状态管理 |
| 6 | 性能 | 内存泄漏、draw call 过多 |

从下往上查（先怀疑自己写的复杂逻辑）是最慢的——因为 90% 的问题出在前两层。
