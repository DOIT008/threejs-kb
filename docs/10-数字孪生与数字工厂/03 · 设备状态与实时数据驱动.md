# 设备状态与实时数据驱动

[上一篇](</10-数字孪生与数字工厂/02 · 三维场景搭建与产线布局>)的车间摆好了，但设备还是"死"的。这篇我们给它们接上"心跳"——让真实（或模拟）的数据流跑起来，设备该绿的时候绿、该红的时候红。这是数字孪生最核心的一章：**数据怎么变成 3D 的颜色和动画**。

## 一、设备状态：四种颜色看懂设备

工厂里状态千千万，但落到视觉上，通常归成四类就够了：

| 状态 | 英文 | 颜色 | 大白话含义 |
|---|---|---|---|
| 运行 | `running` | 🟢 绿 | 机器正干活，一切正常 |
| 待机 | `standby` | 🟡 黄 | 通电但没干活，等着被叫 |
| 报警 | `alarm` | 🔴 红 | 出故障了，要人来管 |
| 离线 | `offline` | ⚪ 灰 | 联系不上，可能是断电/断网 |

::: tip 大白话时间

这四色其实就是**红绿灯 plus**。绿灯走（运行）、黄灯等（待机）、红灯停（报警）、灯灭了（离线）——全世界工人都看得懂，不需要培训。数字孪生用这套颜色，就是为了让人**扫一眼就知道哪台机器出事了**。

:::

## 二、状态机设计表

状态不能随便乱跳——"离线"的设备不可能下一秒突然"运行"，中间得经过"待机"。这种"谁能变成谁"的规矩叫**状态机**。把它写成表，代码里照着实现就行：

| 当前状态 | 触发事件 | 下一个状态 | 视觉表现 |
|---|---|---|---|
| offline | 心跳恢复 / 重新连上 | standby | 灰 → 黄，灯亮起 |
| standby | 收到启动指令 / 开始生产 | running | 黄 → 绿，呼吸灯慢闪 |
| standby | 自检异常 | alarm | 黄 → 红，急促闪烁 |
| running | 完成生产 / 收到停止指令 | standby | 绿 → 黄 |
| running | 温度超限 / 故障信号 | alarm | 绿 → 红，急促闪烁 + 冒泡 |
| alarm | 故障复位 / 人工确认 | standby | 红 → 黄 |
| alarm | 通信中断 | offline | 红 → 灰，灯熄灭 |
| 任意状态 | 心跳超时（连续 N 秒没数据） | offline | 变灰 |

::: warning 注意

表里那条"心跳超时 → offline"特别重要。真实项目里设备可能**悄悄断网**，数据不再上来。如果你不处理，界面会一直显示故障前的"绿色运行"，让人误以为一切正常。**一定要有超时兜底**：超过 N 秒没收到数据，就把设备标成离线灰色。

:::

## 三、接数据：WebSocket / MQTT 是啥，怎么模拟

数据从后端到前端，最常用两条路：

| 方式 | 类比 | 特点 |
|---|---|---|
| **WebSocket** | 一条常开的电话线 | 连上后双方随时说话，延迟低，Web 项目首选 |
| **MQTT** | 对讲机频道 | 发布/订阅模式，设备多、弱网环境更稳 |

前端代码其实长的都差不多——**注册一个"收到消息"的回调**，把数据喂进来：

```js
// WebSocket 版（真实项目大致长这样）
const ws = new WebSocket('wss://你的服务器/ws/device');
ws.onmessage = (e) => {
  const msg = JSON.parse(e.data); // 例如 { id: 'CNC-01', status: 'running', temp: 72 }
  applyDeviceData(msg);           // 把数据交给统一的处理函数
};
```

::: info 信息

**MQTT 在浏览器里**通常用 `mqtt.js` 这个库（`npm i mqtt`），连上 broker 后 `client.subscribe('factory/+/status')`，在 `client.on('message', ...)` 里拿到数据。写法不同，但拿到数据后同样是调 `applyDeviceData(msg)`。**所以把数据入口收敛到一个函数，是这章最重要的设计。** 以后从模拟换真实，只改入口那几行。

:::

本篇先用 `setInterval` 造数据，把 3D 这边完全跑通。你可以理解为：**`setInterval` 假装自己是 WebSocket**。

## 四、数据节流与插值：别让 3D 卡死

真实设备上报数据的频率可能很高——一台设备 100 毫秒一条，100 台设备就是每秒 1000 条。如果每条都立刻去改 3D，浏览器会卡爆。两招解决：

### 招数一：节流（throttle）

不管数据来多快，**最多每 100 毫秒处理一次**。中间到的新数据直接覆盖旧值，不逐条处理。

```js
let lastApply = 0;
function applyDeviceData(msg) {
  const now = performance.now();
  if (now - lastApply < 100) {
    // 还没到 100ms，先记下最新值，不马上更新 3D
    pending.set(msg.id, msg);
    return;
  }
  lastApply = now;
  updateDevice(pending.get(msg.id) || msg); // 只画最新的那一条
}
```

::: tip 大白话时间

节流就像**发朋友圈**：你一小时发生 100 件事，没必要发 100 条。攒着，每隔一会儿发一条"最新动态"就行。看的人不累，你也不累。设备数据也是这个道理——3D 屏幕一秒最多刷 60 帧，每秒更新 1000 次纯属浪费。

:::

### 招数二：插值（lerp）

数据更新有间隔（比如每 100ms 一条），如果颜色"啪"地从绿跳到红，看着很生硬。插值就是**每帧朝目标值靠一点**，形成平滑过渡。

```js
// linear interpolation：current 朝 target 移动一小步
function lerp(current, target, t) {
  return current + (target - current) * t; // t 取 0.05 ~ 0.15
}
// Three.js 的颜色直接有 lerp 方法
material.color.lerp(targetColor, 0.08);
```

`t` 越小越"黏"、过渡越慢；越大越"急"。一般取 `0.05~0.1`，肉眼看着最舒服。

## 五、完整示例：数据流驱动 3D 场景

把前面所有东西合到一起。这个例子里有 6 台设备，头顶各一盏状态灯，`setInterval` 每 150 毫秒随机改一台设备的数据，3D 这边用节流 + 插值平滑地跟着变。真实项目里，把 `feedData()` 换成 WebSocket 的 `onmessage` 即可。

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
  <meta charset="UTF-8" />
  <title>数据流驱动 3D 场景</title>
  <style>
    body { margin: 0; overflow: hidden; background: #0d1117; font-family: sans-serif; }
    #hud { position: fixed; left: 16px; top: 16px; color: #e6edf3;
           background: rgba(0,0,0,.55); padding: 12px 16px; border-radius: 8px;
           font-size: 13px; line-height: 1.9; }
    .badge { display:inline-block; padding: 0 6px; border-radius: 4px; margin-left: 4px; }
  </style>
  <script type="importmap">
  {
    "imports": {
      "three": "https://unpkg.com/three@0.187.0/build/three.module.js",
      "three/addons/": "https://unpkg.com/three@0.187.0/examples/jsm/"
    }
  }
  </script>
</head>
<body>
  <div id="hud">
    <div>实时数据流驱动 3D（每 150ms 一条）</div>
    <div id="counts">统计：加载中…</div>
  </div>

  <script type="module">
  import * as THREE from 'three';
  import { OrbitControls } from 'three/addons/controls/OrbitControls.js';

  // ===== 1. 基础三件套 =====
  const scene = new THREE.Scene();
  scene.background = new THREE.Color(0x0d1117);
  const camera = new THREE.PerspectiveCamera(50, innerWidth / innerHeight, 0.1, 100);
  camera.position.set(9, 8, 12);
  const renderer = new THREE.WebGLRenderer({ antialias: true });
  renderer.setSize(innerWidth, innerHeight);
  renderer.shadowMap.enabled = true;
  renderer.shadowMap.type = THREE.PCFShadowMap;
  document.body.appendChild(renderer.domElement);
  const controls = new OrbitControls(camera, renderer.domElement);
  controls.target.set(0, 0.5, 0);
  controls.enableDamping = true;
  scene.add(new THREE.HemisphereLight(0xaaccff, 0x222233, 1.5));
  const sun = new THREE.DirectionalLight(0xffffff, 2);
  sun.position.set(6, 10, 5); sun.castShadow = true; scene.add(sun);
  const floor = new THREE.Mesh(new THREE.PlaneGeometry(30, 20),
    new THREE.MeshStandardMaterial({ color: 0x1b2230, roughness: 0.95 }));
  floor.rotation.x = -Math.PI / 2; floor.receiveShadow = true; scene.add(floor);
  scene.add(new THREE.GridHelper(30, 30, 0x3b4a63, 0x27334a));

  // ===== 2. 状态定义 =====
  const STATUS = {
    running: { name: '运行', color: 0x42b883 },
    standby: { name: '待机', color: 0xffc107 },
    alarm:   { name: '报警', color: 0xff4d4f },
    offline: { name: '离线', color: 0x555555 }
  };
  const KEYS = Object.keys(STATUS);

  // ===== 3. 造 6 台设备，每台带一盏状态灯 =====
  const devices = new Map(); // id -> 设备对象
  const metal = new THREE.MeshStandardMaterial({ color: 0x64748b, metalness: 0.5, roughness: 0.5 });
  for (let i = 0; i < 6; i++) {
    const id = 'CNC-0' + (i + 1);
    const g = new THREE.Group();
    const body = new THREE.Mesh(new THREE.BoxGeometry(1.4, 1.2, 1.2), metal);
    body.position.y = 0.6; body.castShadow = true; g.add(body);

    // 每盏灯用独立材质，才能单独改颜色
    const lampMat = new THREE.MeshStandardMaterial({
      color: 0x555555, emissive: 0x555555, emissiveIntensity: 0.4
    });
    const lamp = new THREE.Mesh(new THREE.SphereGeometry(0.16, 20, 20), lampMat);
    lamp.position.y = 1.5; g.add(lamp);

    g.position.set((i - 2.5) * 2.4, 0, 0);
    g.userData.id = id;
    scene.add(g);

    devices.set(id, {
      id, group: g,
      lampMat,
      status: 'offline',
      targetColor: new THREE.Color(STATUS.offline.color),
      temp: 25, targetTemp: 25,   // 插值用的当前值 / 目标值
      lastSeen: performance.now() // 心跳时间
    });
  }

  // ===== 4. 数据入口：所有数据都从这里进 =====
  const pending = new Map();       // 节流时暂存最新数据
  let lastApply = 0;
  function applyDeviceData(msg) {
    pending.set(msg.id, msg);      // 不管怎样先记下最新值
    const now = performance.now();
    if (now - lastApply < 100) return; // 100ms 内的其它数据不重复处理
    lastApply = now;
    pending.forEach((m, id) => updateDevice(m));
    pending.clear();
  }

  function updateDevice(msg) {
    const dev = devices.get(msg.id);
    if (!dev) return;
    dev.status = msg.status;
    dev.targetColor.setHex(STATUS[msg.status].color);
    dev.targetTemp = msg.temp ?? dev.targetTemp;
    dev.lastSeen = performance.now(); // 收到数据 = 心跳一次
  }

  // ===== 5. 模拟数据源（真实项目换成 WebSocket / MQTT） =====
  function feedData() {
    const ids = [...devices.keys()];
    const id = ids[Math.floor(Math.random() * ids.length)];
    const status = KEYS[Math.floor(Math.random() * KEYS.length)];
    applyDeviceData({
      id,
      status,
      temp: status === 'offline' ? 25 : 55 + Math.random() * 35
    });
  }
  setInterval(feedData, 150);

  // ===== 6. 心跳超时兜底：8 秒没数据就当离线 =====
  setInterval(() => {
    const now = performance.now();
    devices.forEach(dev => {
      if (now - dev.lastSeen > 8000 && dev.status !== 'offline') {
        updateDevice({ id: dev.id, status: 'offline' });
      }
    });
  }, 2000);

  // ===== 7. 动画循环：插值 + 发光 + HUD =====
  const elCounts = document.getElementById('counts');
  const timer = new THREE.Timer();
  renderer.setAnimationLoop(() => {
    timer.update();
    const t = timer.getElapsed();
    const counts = { running: 0, standby: 0, alarm: 0, offline: 0 };

    devices.forEach(dev => {
      const m = dev.lampMat;
      // 颜色平滑过渡
      m.color.lerp(dev.targetColor, 0.08);
      m.emissive.lerp(dev.targetColor, 0.08);
      // 温度数值插值（演示用，真实项目可绑定到仪表盘）
      dev.temp += (dev.targetTemp - dev.temp) * 0.05;

      // 发光强度按状态变化
      if (dev.status === 'running') m.emissiveIntensity = 0.5 + Math.sin(t * 3) * 0.3;
      else if (dev.status === 'alarm') m.emissiveIntensity = 0.5 + Math.abs(Math.sin(t * 9)) * 1.5;
      else if (dev.status === 'standby') m.emissiveIntensity = 0.35;
      else m.emissiveIntensity = 0.0;

      counts[dev.status]++;
    });

    elCounts.innerHTML = '统计：' +
      KEYS.map(k => `${STATUS[k].name} <b style="color:#${STATUS[k].color.toString(16).padStart(6,'0')}">${counts[k]}</b>`).join('　');

    controls.update();
    renderer.render(scene, camera);
  });

  addEventListener('resize', () => {
    camera.aspect = innerWidth / innerHeight;
    camera.updateProjectionMatrix();
    renderer.setSize(innerWidth, innerHeight);
  });
  </script>
</body>
</html>
```

::: tip 大白话时间

整个例子的"灵魂"其实就一个函数：`applyDeviceData(msg)`。

- 数据不管从 `setInterval` 来，还是从 WebSocket 来，**都先调它**；
- 它做两件事：**节流**（100ms 内只处理一次）+ 把最新值交给 `updateDevice()`；
- `updateDevice()` 只负责改"目标值"（目标颜色、目标温度）；
- 真正的"慢慢变过去"在动画循环里用 `lerp` 完成。

**数据层只管设目标，渲染层只管平滑靠近。** 两层分开，代码清爽，换数据源也不慌。

:::

## 六、小结

| 概念 | 一句话 |
|---|---|
| 状态映射 | 运行绿 / 待机黄 / 报警红 / 离线灰 |
| 状态机 | 规定"谁能变成谁"，离线要有心跳超时兜底 |
| 数据入口 | 收敛到 `applyDeviceData()` 一个函数 |
| 节流 | 100ms 最多处理一次，攒最新值 |
| 插值 | `lerp` 每帧靠一点，变化不突兀 |
