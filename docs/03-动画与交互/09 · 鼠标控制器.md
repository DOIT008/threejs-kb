# 鼠标控制器：让用户转一转

自己监听鼠标事件写相机控制很麻烦。Three.js 官方提供了一堆**控制器**，几行代码就能实现拖拽旋转、滚轮缩放。

## 一、OrbitControls（最常用）

围绕一个目标点旋转查看，产品展示、模型预览基本都用它。

```js
import { OrbitControls } from 'three/addons/controls/OrbitControls.js';

const controls = new OrbitControls(camera, renderer.domElement);

renderer.setAnimationLoop(() => {
  controls.update();  // 用了 damping 时必须每帧调用
  renderer.render(scene, camera);
});
```

### 常用配置

```js
// 手感
controls.enableDamping = true;     // 惯性（松开鼠标后慢慢停）
controls.dampingFactor = 0.05;     // 阻尼系数，越小越顺滑
controls.rotateSpeed = 1.0;        // 旋转速度
controls.zoomSpeed = 1.0;          // 缩放速度
controls.panSpeed = 1.0;           // 平移速度

// 功能开关
controls.enableRotate = true;
controls.enableZoom = true;
controls.enablePan = true;
controls.screenSpacePanning = true; // 平移相对于屏幕，而非世界

// 限制
controls.minDistance = 2;               // 最近能拉多近
controls.maxDistance = 20;              // 最远能拉多远
controls.minPolarAngle = 0;             // 上下转动范围
controls.maxPolarAngle = Math.PI / 2;   // 限制在水平线以上，看不到地下
controls.minAzimuthAngle = -Infinity;   // 左右转动范围
controls.maxAzimuthAngle = Infinity;

// 自动旋转
controls.autoRotate = true;
controls.autoRotateSpeed = 2;

// 围绕哪个点转
controls.target.set(0, 1, 0);
controls.update();
```

::: tip 大白话时间
`target` 就是**转盘的中心**——相机永远绕着这个点转。

如果你的模型在 `(0, 3, 0)`，但没改 `target`（默认原点 `(0,0,0)`），那转起来就是绕着地面转，模型会跑到画面边上去。

**模型在哪，target 就设到哪。**
:::

### 深一层：阻尼到底「阻尼」了什么

很多人知道 `enableDamping = true` 之后必须每帧 `controls.update()`，但不知道为什么。不知道的后果就是：偶尔忘了写，画面看着也「能动」，但怎么都停不下来，或者自动旋转失灵。

::: tip 大白话时间
不开阻尼时，鼠标松手 = 相机立刻定住，像**急刹车**。

开了阻尼，控制器并不直接把相机放到目标位置，而是**每帧往目标位置挪一小步**（挪剩下的 5%）。于是松手后相机还会继续飘一段，像**滑冰慢慢停下**——这就是「惯性」。

既然是「每帧挪一小步」，那当然**必须每帧调用 `update()` 才有人挪**。只调一次，它只挪一步就永远停住了。
:::

```js
controls.enableDamping = true;
controls.dampingFactor = 0.05; // 每帧靠近目标的 5%，越小越顺、停得越慢

renderer.setAnimationLoop(() => {
  controls.update(); // ← 这行不能省，也不能改成只在鼠标事件里调
  renderer.render(scene, camera);
});
```

**几个真实项目里的坑：**

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 相机松手后还在缓慢飘，停不下来 | `dampingFactor` 设太小，比如 0.01 | 调到 0.05~0.1；或者关掉阻尼 |
| 页面切后台再回来，相机突然跳一下 | 后台帧率极低，阻尼累积步数不对 | 切回来调一次 `controls.update()`，或暂停动画循环 |
| 自动旋转 `autoRotate` 不动 | 同样忘了每帧 `update()` | 补上 |
| 给用户提供「重置视角」按钮后失效 | 只改了 `camera.position`，没清控制器的内部状态 | 见下方代码 |

**正确重置视角：**

```js
function resetView() {
  camera.position.set(5, 4, 8);
  controls.target.set(0, 0.5, 0);
  controls.update(); // 关键：让控制器重新计算内部球坐标
}
```

::: warning 别直接改 camera.position 就算完
`OrbitControls` 内部维护的是「以 target 为中心的球坐标（半径 + 极角 + 方位角）」，不是直接读 `camera.position`。你只改相机位置，控制器下一次 `update()` 会把相机拉回它自己记的位置——看起来就像「重置按钮没用」。改完必须 `controls.update()`。
:::

### 鼠标操作对照

| 操作 | 效果 |
|---|---|
| 左键拖拽 | 旋转 |
| 滚轮 / 双指捏合 | 缩放 |
| 右键拖拽 / 双指拖动 | 平移 |
| 双击? | 无（需自己实现） |

## 二、其他控制器

```js
// 飞行视角（像开飞机，WASD + 鼠标）
import { FlyControls } from 'three/addons/controls/FlyControls.js';

// 第一人称（FPS 游戏，指针锁定）
import { PointerLockControls } from 'three/addons/controls/PointerLockControls.js';

// 编辑器风格（拖拽移动/旋转/缩放物体的小工具）
import { TransformControls } from 'three/addons/controls/TransformControls.js';

// 像地图一样平移拖拽（OrbitControls 的变体）
import { MapControls } from 'three/addons/controls/MapControls.js';

// 直接拖动物体（Raycaster 封装）
import { DragControls } from 'three/addons/controls/DragControls.js';

// 轨迹球（自由旋转，没有极角限制）
import { TrackballControls } from 'three/addons/controls/TrackballControls.js';
```

**怎么选？按用户要「怎么动」来选：**

| 用户想做的事 | 选哪个 | 典型场景 |
| --- | --- | --- |
| 围着一个东西转着看 | `OrbitControls` | 产品展示、模型预览、数字孪生总览 |
| 像地图一样拖来拖去 | `MapControls` | 平面图、园区地图、GIS |
| 第一人称在里面走 | `PointerLockControls` | 展厅漫游、FPS 小游戏 |
| 像开飞机自由飞 | `FlyControls` | 场景巡检、自由探索 |
| 直接拖某个零件 | `DragControls` | 拖拽摆放、简单编辑器 |
| 带手柄地移动/旋转/缩放零件 | `TransformControls` + `OrbitControls` | 3D 编辑器、搭场景工具 |
| 完全自由地滚球式旋转 | `TrackballControls` | 分子结构、抽象模型查看 |

::: warning 选择时最容易错的两点
1. **`PointerLockControls` 需要用户主动授权**（点击页面锁定鼠标指针），不能一进页面就强制锁定，否则用户会很懵。
2. **`TransformControls` 不是相机控制器**，它是操作物体的。必须和 `OrbitControls` 搭配，并按上一节讲的用 `dragging-changed` 事件互斥。
:::

## 三、多控制器共存

编辑器里经常需要「平时用 OrbitControls 转视角，点中物体后切换成 TransformControls 拖拽」：

```js
transformControls.addEventListener('dragging-changed', e => {
  orbitControls.enabled = !e.value; // 拖拽物体时暂时禁用轨道控制
});
```

::: tip 大白话时间
两个控制器同时监听鼠标会「打架」——你拖物体，相机也跟着转。

所以拖物体的时候，先把 OrbitControls 临时关掉，松手再打开。这个 `dragging-changed` 事件就是干这个的。
:::

## 四、移动端适配

OrbitControls 原生支持触摸：单指旋转、双指缩放/平移。但要注意：

```js
renderer.domElement.style.touchAction = 'none'; // 阻止页面滚动干扰
```

::: warning 注意
如果页面在手机上能滚动，触摸拖拽 3D 场景时可能连带页面一起滚。给 canvas 加 `touch-action: none` 能解决。
:::

## 五、销毁：别忘了 dispose

控制器内部注册了一堆 DOM 事件监听。**组件卸载时只删 canvas 是不够的**——监听还挂在 window / document 上，切几次页面就会有几个控制器在同时响应鼠标，表现为「拖拽一下相机转好几倍」。

```js
// Vue3 里
onUnmounted(() => {
  controls.dispose();
  renderer.dispose();
  renderer.domElement.remove();
});
```

::: danger 多出一份控制器 = 多一份事件监听
这是 SPA 里非常隐蔽的 bug：页面切走又回来，看似一切正常，但相机转动速度变快了。每切一次快一倍，切五次就没法用了。

判断方法：在 `pointermove` 回调里打日志，看一次鼠标移动触发几次。正常情况下应该只有一次。
:::
