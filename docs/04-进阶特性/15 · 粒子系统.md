# 粒子系统：星空、烟雾、魔法特效

粒子就是一堆**小点**。几千几万个点一起动，就能做出星空、雪花、烟花、萤火虫等效果。

::: tip 大白话时间
一个点渲染起来很便宜。一万个点同时渲染，比一万个立方体快得多——因为点不需要复杂的几何体和光照计算。

所以特效领域有个潜规则：**能用粒子就别用模型。**
:::

## 一、Points 基本用法

```js
// 1. 准备顶点数据：每个粒子 3 个坐标
const count = 1000;
const positions = new Float32Array(count * 3);

for (let i = 0; i < count; i++) {
  positions[i * 3]     = (Math.random() - 0.5) * 10; // x
  positions[i * 3 + 1] = (Math.random() - 0.5) * 10; // y
  positions[i * 3 + 2] = (Math.random() - 0.5) * 10; // z
}

// 2. 创建 BufferGeometry
const geometry = new THREE.BufferGeometry();
geometry.setAttribute('position', new THREE.BufferAttribute(positions, 3));

// 3. 粒子材质
const material = new THREE.PointsMaterial({
  color: 0x42b883,
  size: 0.05,          // 点的大小
  sizeAttenuation: true, // 远小近大（透视）
  transparent: true,
  opacity: 0.8
});

// 4. 创建粒子系统
const particles = new THREE.Points(geometry, material);
scene.add(particles);
```

## 二、让粒子动起来

直接改顶点数据，然后标记需要更新：

```js
const positions = geometry.attributes.position.array;

renderer.setAnimationLoop(() => {
  for (let i = 0; i < count; i++) {
    positions[i * 3 + 1] += 0.01; // 每个粒子往上飘

    // 飘出范围后回到底部
    if (positions[i * 3 + 1] > 5) {
      positions[i * 3 + 1] = -5;
    }
  }

  geometry.attributes.position.needsUpdate = true; // 关键！

  // 关键但极易漏：包围球还是加载时的，位置变了不重算会被视锥剔除误杀
  geometry.computeBoundingSphere();

  renderer.render(scene, camera);
});
```

::: warning 注意
改完顶点数据必须设 `needsUpdate = true`，否则 GPU 不知道数据变了，画面不会更新。

粒子数很多时，每帧遍历所有粒子改位置会吃 CPU。上万粒子建议用着色器在 GPU 上算（进阶内容）。
:::

### 深一层：为什么粒子会「转个头就没了」

这是粒子系统最隐蔽的 bug：粒子明明还在视野里，相机一转，整团粒子突然消失。

::: tip 大白话时间
Three.js 为了省性能，会给每个物体算一个**包围球**——一个刚好装下所有顶点的球。相机先看这个球在不在视野里，不在就整个物体跳过不画。

问题在于：**这个球只在创建时算过一次**。你把粒子往上飘了 5 个单位，球还在原地。相机转向新位置后，Three.js 一查「旧球不在视野内」，就把整团粒子剔除了——哪怕粒子本身就在眼前。
:::

两种解法，按场景选：

```js
// 方案 A：每帧重算包围球（粒子数不多时最简单，几千个点是毫秒级）
geometry.computeBoundingSphere();

// 方案 B：粒子活动范围固定且已知，手动给一个足够大的球，一劳永逸
geometry.boundingSphere = new THREE.Sphere(
  new THREE.Vector3(0, 0, 0), // 球心
  100                        // 半径，覆盖所有粒子可能到达的位置
);

// 方案 C：彻底关掉这个物体的视锥剔除（最后的手段，会牺牲一点性能）
particles.frustumCulled = false;
```

::: warning 什么时候不用管
如果粒子只是**整体旋转/平移**（像第五节星空那样只转 `stars.rotation.y`），包围球会跟着物体变换走，不需要重算。**只有逐顶点改位置时才要处理。**
:::

### 深一层：CPU 粒子还是 GPU 粒子？

上面那种「每帧 JS 循环改顶点」是 **CPU 粒子**。它直观、好调试，但有天花板。什么时候该换 GPU 方案？看这张表：

| 维度 | CPU 粒子（本章写法） | GPU 粒子（着色器 / TSL） |
| --- | --- | --- |
| 适合规模 | 几百 ~ 几千 | 几万 ~ 几百万 |
| 每个粒子的行为 | 可以各不相同，随便写 if | 必须能用统一公式表达 |
| 与物理/业务逻辑交互 | 容易（能直接读游戏状态） | 难（数据在 GPU 上，读回来很贵） |
| CPU 开销 | 每帧 O(n) 循环，粒子多了必卡 | 几乎为零 |
| 调试难度 | 打 console.log 就能看 | 只能靠值和画面猜 |
| 代表场景 | 点击爆炸、粒子跟随鼠标 | 星空、烟花、雪花、银河 |

**判断标准就一句话：如果每个粒子的运动能写成一个数学公式，就搬去 GPU。**

```js
// CPU 版：JS 里一个个算（几千个还行）
for (let i = 0; i < count; i++) {
  positions[i * 3 + 1] += 0.01;
}

// GPU 版思路：把「起始位置 + 速度 + 时间」交给顶点着色器
// position.y = mod(aStart.y + aSpeed * uTime, 10.0) - 5.0;
// JS 每帧只改一个 uTime，几百万个点一起算
```

::: tip 大白话时间
CPU 粒子像**老师挨个给全班同学改卷子**——人越多越慢。

GPU 粒子像**广播通知**：老师只喊一句「现在是第 5 秒」，全班同学自己按公式算自己该站哪。喊话只要一次，几千人同时动。
:::

::: warning 别过早优化
几千个粒子用 CPU 完全没问题，代码简单得多。**等到真的掉帧了再搬 GPU**——迁移成本不低，而且很多效果（比如点击后某个粒子单独飞走）本来就不适合 GPU 方案。

想先看效果，可以用交互实验室的「粒子系统实验室」，它有 2 万粒子的实时演示，能直观感受两种规模的区别。
:::

## 三、给粒子上色

```js
const colors = new Float32Array(count * 3);
for (let i = 0; i < count; i++) {
  const c = new THREE.Color().setHSL(Math.random(), 1, 0.5);
  colors[i * 3]     = c.r;
  colors[i * 3 + 1] = c.g;
  colors[i * 3 + 2] = c.b;
}
geometry.setAttribute('color', new THREE.BufferAttribute(colors, 3));

const material = new THREE.PointsMaterial({
  size: 0.1,
  vertexColors: true  // 开启顶点颜色
});
```

## 四、自定义粒子形状

默认的点是方块。用贴图可以让它变圆、变星光：

```js
// 画个圆形渐变
const canvas = document.createElement('canvas');
canvas.width = canvas.height = 64;
const ctx = canvas.getContext('2d');
const grad = ctx.createRadialGradient(32, 32, 0, 32, 32, 32);
grad.addColorStop(0, 'rgba(255,255,255,1)');
grad.addColorStop(1, 'rgba(255,255,255,0)');
ctx.fillStyle = grad;
ctx.fillRect(0, 0, 64, 64);

const texture = new THREE.CanvasTexture(canvas);

const material = new THREE.PointsMaterial({
  size: 0.2,
  map: texture,          // 用贴图
  transparent: true,
  depthWrite: false,     // 关闭深度写入，避免透明粒子互相遮挡
  blending: THREE.AdditiveBlending // 叠加混合，发光效果
});
```

::: tip 大白话时间
`AdditiveBlending`（叠加混合）是做发光特效的秘密武器——多个粒子重叠时颜色会**相加**，越叠越亮，像真的光一样。

配合 `depthWrite: false` 使用，否则后面的粒子会被前面的「挡住」，光晕效果就没了。
:::

## 五、实战：星空背景

```js
const count = 3000;
const positions = new Float32Array(count * 3);
const colors = new Float32Array(count * 3);

for (let i = 0; i < count; i++) {
  // 球壳上随机分布
  const r = 50 + Math.random() * 50;
  const theta = Math.random() * Math.PI * 2;
  const phi = Math.acos(2 * Math.random() - 1);

  positions[i*3]     = r * Math.sin(phi) * Math.cos(theta);
  positions[i*3 + 1] = r * Math.cos(phi);
  positions[i*3 + 2] = r * Math.sin(phi) * Math.sin(theta);

  const c = new THREE.Color().setHSL(0.6 + Math.random() * 0.1, 0.5, 0.6 + Math.random() * 0.4);
  colors[i*3] = c.r; colors[i*3+1] = c.g; colors[i*3+2] = c.b;
}

const geo = new THREE.BufferGeometry();
geo.setAttribute('position', new THREE.BufferAttribute(positions, 3));
geo.setAttribute('color', new THREE.BufferAttribute(colors, 3));

const stars = new THREE.Points(geo, new THREE.PointsMaterial({
  size: 0.8,
  vertexColors: true,
  sizeAttenuation: true,
  transparent: true,
  depthWrite: false
}));
scene.add(stars);

// 缓慢旋转整个星空
renderer.setAnimationLoop(() => {
  stars.rotation.y += 0.0002;
  renderer.render(scene, camera);
});
```
