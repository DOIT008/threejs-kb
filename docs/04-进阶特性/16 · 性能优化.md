# 性能优化：让页面不卡

3D 项目最怕「卡」。这一章整理最常见的优化手段。

::: tip 大白话时间
显卡每秒能画的三角形数量是有限的。优化的核心思想就两条：

1. **少画**：看不见的别画，重复的合并画
2. **画简单点**：远处用简化模型，能用贴图骗的就别真建模型
:::

## 一、先测量，再优化

```js
// 渲染信息
console.log(renderer.info.render.calls);      // draw call 次数（最重要！）
console.log(renderer.info.render.triangles);  // 三角形数量
console.log(renderer.info.memory.geometries); // 几何体数量
console.log(renderer.info.memory.textures);   // 纹理数量
```

::: tip 关键指标
**Draw Call（绘制调用）** 是最关键的性能指标。每个 Mesh 至少一次 draw call。1000 个独立小立方体 = 1000 次调用，显卡会累死。

目标：控制在几百次以内。
:::

## 二、InstancedMesh：批量渲染相同物体

一万个相同物体，不用创建一万个 Mesh，用一个 `InstancedMesh`：

```js
const geometry = new THREE.BoxGeometry(0.1, 0.1, 0.1);
const material = new THREE.MeshStandardMaterial({ color: 0x42b883 });
const count = 10000;

const instanced = new THREE.InstancedMesh(geometry, material, count);
const dummy = new THREE.Object3D(); // 辅助对象，用来算变换矩阵

for (let i = 0; i < count; i++) {
  dummy.position.set(
    (Math.random() - 0.5) * 50,
    (Math.random() - 0.5) * 50,
    (Math.random() - 0.5) * 50
  );
  dummy.rotation.set(Math.random() * Math.PI, Math.random() * Math.PI, 0);
  dummy.updateMatrix();
  instanced.setMatrixAt(i, dummy.matrix);
}

scene.add(instanced);
```

::: tip 大白话时间
`InstancedMesh` 就像**盖章**：几何体和材质只准备一份，然后告诉 GPU「把这个形状在 10000 个位置各画一遍」。

原本 10000 次 draw call，现在 1 次。性能提升是**几十倍**级别的。

草原上的草、森林里的树、满天星星——都该用它。
:::

### 深一层：BatchedMesh——形状不同也能合批

`InstancedMesh` 有个硬限制：**所有实例必须是同一个几何体**。但城市街区里楼的形状各不相同，怎么办？r187 的 `BatchedMesh` 可以把**不同几何体**塞进同一个 draw call：

```js
// 三个上限要提前估好：实例数、总顶点数、总索引数
const batched = new THREE.BatchedMesh(
  100,     // 最多 100 个实例
  30000,   // 所有几何体顶点总数上限
  60000    // 所有几何体索引总数上限
);

// 支持多种形状，每种形状登记一次
const boxId  = batched.addGeometry(new THREE.BoxGeometry(1, 1, 1));
const coneId = batched.addGeometry(new THREE.ConeGeometry(0.5, 2, 8));

const matrix = new THREE.Matrix4();
for (let i = 0; i < 100; i++) {
  const geometryId = i % 2 === 0 ? boxId : coneId;
  const instanceId = batched.addInstance(geometryId);

  matrix.makeTranslation((i % 10) * 2, 0, Math.floor(i / 10) * 2);
  batched.setMatrixAt(instanceId, matrix);
  // batched.setColorAt(instanceId, color); // 也支持逐实例颜色
}

scene.add(batched);

// 隐藏某个实例（比删了再加回来便宜）
batched.setVisibleAt(3, false);
```

::: warning 三个限制
- **上限要预留够。** `addGeometry` 时顶点/索引超上限会报错；估不准就往大了给，但别太离谱（显存按上限预分配）。
- **一个 `BatchedMesh` 只能有一种材质。** 不同材质的物体得分成多个 `BatchedMesh`。
- **它是较新的 API。** 先在项目实际浏览器环境跑一遍再上生产；老设备遇到问题就退回「普通 Mesh + 合并几何体」。
:::

### 给实例单独上色

```js
const color = new THREE.Color();
for (let i = 0; i < count; i++) {
  color.setHSL(Math.random(), 1, 0.5);
  instanced.setColorAt(i, color);
}

```

## 三、几何体合并

多个不同几何体合成一个，减少 draw call：

```js
import { mergeGeometries } from 'three/addons/utils/BufferGeometryUtils.js';

const geometries = [];
for (let i = 0; i < 100; i++) {
  const geo = new THREE.BoxGeometry(1, 1, 1);
  geo.translate(i * 2, 0, 0); // 设置位置
  geometries.push(geo);
}

const merged = mergeGeometries(geometries);
const mesh = new THREE.Mesh(merged, material);
scene.add(mesh);
```

::: warning 注意
合并后的物体**不能再单独移动**——所有几何体变成一个整体了。适合合并静态景物（建筑、地板），不适合会动的角色。
:::

## 四、LOD（细节层级）

远处用简化模型，近处用精细模型：

```js
import * as THREE from 'three';

// 三档几何体：面数逐级下降（这里用球体举例，真实项目是导出的模型）
const highGeo = new THREE.SphereGeometry(1, 64, 32); // 约 4000 面
const midGeo  = new THREE.SphereGeometry(1, 16, 8);  // 约 250 面
const lowGeo  = new THREE.SphereGeometry(1, 8, 4);   // 约 64 面

const material = new THREE.MeshStandardMaterial({ color: 0x42b883 });
const lod = new THREE.LOD();

const highDetail = new THREE.Mesh(highGeo, material);  // 精细版
const midDetail  = new THREE.Mesh(midGeo, material);   // 中等版
const lowDetail  = new THREE.Mesh(lowGeo, material);   // 简化版

lod.addLevel(highDetail, 0);   // 0 米内用精细版
lod.addLevel(midDetail, 20);   // 20 米外用中等版
lod.addLevel(lowDetail, 50);   // 50 米外用简化版

scene.add(lod);
```

::: tip 大白话时间
LOD 是「**远看轮廓，近看细节**」。

一个远处的路人，你根本看不清他的脸，没必要渲染 10000 个面。Three.js 会根据距离自动切换模型版本，用户完全感知不到。
:::

## 五、视锥剔除

Three.js **默认开启**视锥剔除（frustum culling）——相机看不到的物体自动不渲染。

但有时需要关闭（比如粒子系统被意外剔除）：

```js
mesh.frustumCulled = false;
```

确保几何体有正确的包围盒：

```js
geometry.computeBoundingSphere();
```

## 六、纹理优化

- 图片尺寸用 2 的幂（512、1024、2048）——GPU 处理最高效
- 用压缩纹理格式（KTX2、Basis）——体积和显存都省
- 复用纹理，别重复加载同一张图
- 移动端限制纹理尺寸（2048 以下）

## 七、渲染器设置

```js
// 限制像素比（高清屏上很有效）
renderer.setPixelRatio(Math.min(devicePixelRatio, 2));

// 移动端降到 1
if (isMobile) renderer.setPixelRatio(1);

// 关闭不需要的特性
renderer.shadowMap.enabled = false;  // 不用阴影就关
renderer.antialias = false;          // 用后期 AA 时可以关
```

## 八、内存管理：dispose 的完整套路

`scene.remove(mesh)` 只是把物体从场景树里摘掉，**显存一个字节都不会释放**。不调用 `dispose()`，切几次场景显存就爆了——SPA 路由切换、弹窗反复打开时最容易中招。

一个能覆盖 90% 场景的递归释放函数：

```js
function disposeObject(root) {
  const geometries = new Set();
  const materials = new Set();
  const textures = new Set();

  root.traverse((obj) => {
    if (obj.geometry) geometries.add(obj.geometry);

    const mats = Array.isArray(obj.material) ? obj.material : [obj.material];
    mats.forEach((mat) => {
      if (!mat) return;
      materials.add(mat);

      // 材质上所有可能的贴图槽位都要收进去
      Object.values(mat).forEach((value) => {
        if (value?.isTexture) textures.add(value);
      });
    });
  });

  textures.forEach((tex) => tex.dispose());
  materials.forEach((mat) => mat.dispose());
  geometries.forEach((geo) => geo.dispose());

  root.parent?.remove(root); // 最后再从场景里摘掉
}

// 用的时候
disposeObject(robotModel);
```

**为什么用 `Set`？** 因为多个 Mesh 经常共用同一个几何体或材质（尤其 `InstancedMesh` 和克隆出来的物体）。直接对每个物体调 `dispose()` 会重复释放同一个资源，虽然不报错，但容易漏掉「还有人在用却被释放」的情况。

**除了物体本身，这些也要手动清：**

```js
// 后期处理
composer.dispose();
composer.passes.forEach(pass => pass.dispose?.());

// 渲染目标
renderTarget.dispose();

// 控制器 / 事件监听
controls.dispose();
renderer.domElement.removeEventListener('pointermove', onMove);

// 最后才销毁渲染器
renderer.dispose();
renderer.forceContextLoss(); // 主动丢掉 WebGL 上下文，浏览器立刻回收显存
```

::: tip 大白话时间
把显存想成**公司工位**。`scene.remove()` 只是把人从工位上叫走了，桌子、椅子、电脑还占着。

`dispose()` 才是真的把设备还回仓库。人走了不还设备，来新人就没地方坐——这就是「切了几个页面就越来越卡」的原因。
:::

::: warning 共享资源别乱 dispose
如果一张贴图被多个场景共用（比如全局的 logo），别在销毁某个场景时把它 `dispose()` 了，否则别的场景会变成黑块。

解决办法：全局共享资源单独管理，只在整个应用退出时释放；或者用引用计数。
:::

**怎么验证到底泄没泄漏？**

```js
// 每次切换场景前后打印一次
console.log(renderer.info.memory.geometries, renderer.info.memory.textures);
```

反复进入/退出场景 10 次，如果这两个数字**一路涨不回落**，就是漏了。注意 `dispose()` 后计数不会立刻变，下一帧渲染后才更新——测的时候等一帧再看。更完整的排查流程见[「性能剖析与调优」](</09-生产级专题/03 · 性能剖析与调优>)和[「内存管理与泄漏排查」](</09-生产级专题/01 · 内存管理与泄漏排查>)两篇。

## 九、优化清单

| 问题 | 解决方案 |
|---|---|
| Draw call 太多 | InstancedMesh / 合并几何体 |
| 三角形太多 | 降低分段数 / LOD / 简化模型 |
| 纹理太大 | 压缩纹理 / 降低分辨率 |
| 后期处理卡 | 减少 Pass / 降低像素比 |
| 阴影卡 | 降低 mapSize / 减少投影灯 |
| 内存泄漏 | 及时 dispose() |
| 移动端卡 | 关阴影、降像素比、关后期 |
