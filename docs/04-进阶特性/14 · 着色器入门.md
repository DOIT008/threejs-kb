# 着色器 Shader：从「会用」到「会创造」

前面所有材质都是 Three.js 提供的「成品」。想做水波、火焰、溶解、全息投影这些独特效果，就得自己写**着色器**。

::: tip 大白话时间
着色器是运行在 **GPU 上的小程序**，它告诉显卡：「每个像素应该是什么颜色」。

普通程序在 CPU 上跑，一次算一个东西；着色器在 GPU 上跑，**几百万个像素同时算**——这就是它能实时渲染 3D 的原因。
:::

## 一、着色器的两种类型

| 类型 | 英文名 | 作用 | 运行次数 |
|---|---|---|---|
| 顶点着色器 | Vertex Shader | 决定顶点在哪 | 每个顶点一次 |
| 片元着色器 | Fragment Shader | 决定像素什么颜色 | 每个像素一次 |

::: tip 大白话时间
想象画画：

1. **顶点着色器**先摆好画板上的「骨架」（三角形的三个角在哪）
2. **片元着色器**再给骨架内部的每一个像素「上色」

两步配合，就画出了一张图。
:::

### 先看清路线：一段顶点数据怎么变成屏幕上的像素

写 shader 时最容易迷路的地方是「我这段代码到底在哪个阶段跑」。整条路线（渲染管线）其实就五步：

```txt
CPU 准备 BufferGeometry（position / uv / normal）
        ↓ 上传 GPU
① 顶点着色器   每个顶点跑一次 → 算出 gl_Position（顶点在屏幕上的位置）
        ↓
② 图元装配     三个顶点拼成一个三角形
        ↓
③ 光栅化       三角形内部的每个像素变成一个「片元」
        ↓
④ 片元着色器   每个片元跑一次 → 算出 gl_FragColor（这个像素什么颜色）
        ↓
⑤ 输出合并     深度测试、混合 → 写进帧缓冲 → 上屏
```

::: tip 大白话时间
顶点着色器决定「**画在哪**」，片元着色器决定「**什么色**」。

`varying` 是两者之间的传话筒：顶点着色器在每个顶点上填好值，GPU 在三角形内部**自动插值**，片元着色器拿到的就是每个像素自己的那一份。这就是为什么 UV 坐标能从 3 个顶点扩散到整张面。
:::

理解这张图后，很多报错就不用猜了：

- 顶点没出现在预期位置 → 查 ①（`gl_Position` 的矩阵乘法）
- 颜色是全黑/全白 → 查 ④（`gl_FragColor`、uniform 有没有传进来）
- 明明写了颜色却看不见 → 查 ⑤（`depthTest`、`transparent`、`blending`）

## 二、ShaderMaterial 最简例子

```js
const material = new THREE.ShaderMaterial({
  // 传给着色器的自定义数据（uniform = 全局变量）
  uniforms: {
    uTime: { value: 0 },
    uColor: { value: new THREE.Color(0x42b883) }
  },

  vertexShader: `
    varying vec2 vUv;

    void main() {
      vUv = uv;  // 把 UV 坐标传给片元着色器
      // 标准变换：把顶点从本地坐标变成屏幕坐标
      gl_Position = projectionMatrix * modelViewMatrix * vec4(position, 1.0);
    }
  `,

  fragmentShader: `
    uniform float uTime;
    uniform vec3 uColor;
    varying vec2 vUv;

    void main() {
      // 用 sin 波做个上下流动的颜色渐变
      float wave = sin(vUv.y * 10.0 + uTime * 2.0) * 0.5 + 0.5;
      vec3 color = uColor * wave;
      gl_FragColor = vec4(color, 1.0);
    }
  `
});

// 动画循环里更新时间
renderer.setAnimationLoop(() => {
  material.uniforms.uTime.value = performance.now() / 1000;
  renderer.render(scene, camera);
});
```

## 三、三个关键概念

### uniform

从 JavaScript 传给着色器的**全局变量**，所有顶点/像素共享同一个值。常用于时间、颜色、鼠标位置。

```js
uniforms: {
  uTime: { value: 0 },           // float
  uColor: { value: new THREE.Color('red') }, // vec3
  uTexture: { value: texture }   // sampler2D
}
```

::: tip 大白话时间
`uniform` 是 JS 和 GPU 之间的**传话筒**。你想让 GPU 知道「现在是第几秒」，就通过 uniform 传进去。

命名习惯加 `u` 前缀（`uTime`、`uColor`），一眼就能认出是 uniform。
:::

### varying

顶点着色器传给片元着色器的**桥梁数据**。最常用的是 `uv`（纹理坐标）和 `normal`（法线）。

```js
// 顶点着色器
varying vec2 vUv;
vUv = uv;

// 片元着色器
varying vec2 vUv;  // 名字必须一致
```

### GLSL 基础类型

```glsl
float  // 浮点数
vec2   // 二维向量 (x, y)
vec3   // 三维向量 (x, y, z) 或颜色 (r, g, b)
vec4   // 四维向量 (x, y, z, w) 或颜色 (r, g, b, a)
mat4   // 4x4 矩阵
sampler2D // 纹理
```

常用函数：`sin()`, `cos()`, `mix()`, `smoothstep()`, `clamp()`, `length()`, `normalize()`, `fract()`

## 四、实用效果示例

### 波纹效果

```glsl
// 片元着色器核心
float dist = distance(vUv, vec2(0.5));
float wave = sin(dist * 30.0 - uTime * 5.0) * 0.5 + 0.5;
vec3 color = mix(colorA, colorB, wave);
gl_FragColor = vec4(color, 1.0);
```

### 溶解效果

```glsl
// 用噪声纹理决定哪些像素消失
float noise = texture2D(uNoise, vUv).r;
if (noise < uProgress) discard;  // 丢弃像素

// 边缘发光
float edge = smoothstep(uProgress, uProgress + 0.1, noise);
vec3 color = mix(glowColor, baseColor, edge);
```

::: tip 小贴士
`discard` 会直接丢弃当前像素（不绘制），做溶解、镂空效果很方便。
:::

### 深一层：onBeforeCompile——只改一小块，不重写整件衣服

`ShaderMaterial` 要自己把光照、阴影、雾全写一遍，门槛高。大多数需求其实只是「想把内置材质改一小点」——比如加个波浪、做个溶解边缘。这时候用 `onBeforeCompile`：

::: tip 大白话时间
`ShaderMaterial` 相当于**自己裁布做一整件衣服**；`onBeforeCompile` 是**买一件现成外套，在袖子上绣个图案**。

布料、走线、版型（光照、阴影、雾）全是 Three.js 帮你做好的，你只改那一小块。改完还是那件外套，该有的功能一个不少。
:::

```js
const material = new THREE.MeshStandardMaterial({ color: 0x42b883 });

// 共享 uniform 对象：每帧改它的 value，GPU 就能收到新值
const uniforms = { uTime: { value: 0 } };

material.onBeforeCompile = (shader) => {
  // ① 把自己的 uniform 塞进 shader
  shader.uniforms.uTime = uniforms.uTime;

  // ② 在 common 块后面声明变量
  shader.vertexShader = shader.vertexShader.replace(
    '#include <common>',
    '#include <common>\nuniform float uTime;'
  );

  // ③ begin_vertex 之后 transformed 才存在，在它后面加位移
  shader.vertexShader = shader.vertexShader.replace(
    '#include <begin_vertex>',
    `#include <begin_vertex>
     transformed.y += sin(transformed.x * 4.0 + uTime * 2.0) * 0.15;`
  );
};

// ④ 关键：不同 patch 的材质要有不同的缓存 key，否则 Three.js 会复用错 shader
material.customProgramCacheKey = () => 'wave-v1';

renderer.setAnimationLoop(() => {
  uniforms.uTime.value = performance.now() / 1000;
  renderer.render(scene, camera);
});
```

**四个必须记住的点：**

| 点 | 为什么 |
| --- | --- |
| `shader.uniforms.uTime = uniforms.uTime` 传的是**同一个对象引用** | 这样每帧改外面的 `value` 才会同步到 GPU；复制一份就没效果了 |
| 声明变量放在 `#include <common>` 后 | 这是 Three.js 内置 shader 的「头文件区」，放这里不会被后面的宏展开干掉 |
| 改顶点放在 `#include <begin_vertex>` 后 | `transformed` 这个变量就是在这里定义的，放前面会报 `undeclared identifier` |
| `customProgramCacheKey()` 返回唯一字符串 | Three.js 按 key 缓存编译结果。两个材质 patch 不同但 key 相同 → 后一个会用到前一个的 shader，出现「怎么改都不生效」的怪现象 |

**怎么知道该替换哪个 `#include`？**

去 `node_modules/three/src/renderers/shaders/ShaderLib/` 里找对应材质的 shader 源码，或者直接在 `onBeforeCompile` 里 `console.log(shader.vertexShader)` 打印出来看。所有 `#include <xxx>` 对应 `node_modules/three/src/renderers/shaders/ShaderChunk/` 里的文件。

::: warning 版本提示
`onBeforeCompile` 是 **WebGLRenderer** 的 API。切换到 WebGPURenderer 后它不会生效，要改用下面一节讲的 Node Material / TSL。
:::

## 五、Node Material（WebGPU 新方向）

r187 里，Three.js 主推的 **WebGPURenderer** 提供了新的 **Node Material** 系统——用 JavaScript 拼装节点来写材质，不用直接写 GLSL。

先看清它跟 WebGL 项目最大的区别：**渲染器初始化是异步的**。`WebGPURenderer` 必须先 `await renderer.init()`，不能像 `WebGLRenderer` 那样 `new` 完直接 render：

```js
import * as THREE from 'three/webgpu';

const renderer = new THREE.WebGPURenderer({ antialias: true });
renderer.setSize(innerWidth, innerHeight);
document.body.appendChild(renderer.domElement);

await renderer.init(); // 必须等！否则 GPU 设备还没准备好

renderer.setAnimationLoop(() => {
  renderer.render(scene, camera);
});
```

在 Vue3 的 `onMounted` 里用就把初始化函数写成 `async`；不支持 WebGPU 的浏览器可以显式回退到 WebGL2 后端：

```js
const renderer = new THREE.WebGPURenderer({
  forceWebGL: !navigator.gpu  // 没有 WebGPU 时用 WebGL2 后端跑同一套 Node Material
});
```

然后才是材质部分：

```js
import * as THREE from 'three/webgpu';
import { color, uv, sin, time, mix, vec3 } from 'three/tsl';

const material = new THREE.MeshBasicNodeMaterial();
const wave = sin(uv().y.mul(10).add(time.mul(2))).mul(0.5).add(0.5);
material.colorNode = mix(color(0x42b883), color(0xff0000), wave);
```

::: tip 大白话时间
传统 ShaderMaterial 要写 GLSL 字符串（像另一门语言）。Node Material 让你用 **JavaScript 函数拼装**效果——`sin()`、`mix()` 这些都能像搭积木一样组合。

对不熟悉 GLSL 的 JS 开发者友好很多。这是未来方向，但传统 ShaderMaterial 依然完全可用。
:::

### 深一层：该用哪种写法？一张决策表

| 你的需求 | 用什么 | 理由 |
| --- | --- | --- |
| 只想让材质多点颜色变化/波纹 | `onBeforeCompile` | 保留内置光照阴影，改动最小 |
| 要完整自定义外观，不需要光照 | `ShaderMaterial` | 从零写，最自由 |
| 要自定义外观但仍需 Three.js 的光照/阴影 | `ShaderMaterial` + `lights: true` + 内置 chunk | 复杂，但可行 |
| 做全屏特效（辉光、模糊、色调） | `EffectComposer` + `ShaderPass` | 作用在最终画面而不是单个物体 |
| 项目已迁到 WebGPU | Node Material / TSL | WebGL 的 shader 写法不通用 |
| 只是想调参数看效果 | 交互实验室的「辉光实验室」 | 不写代码，先建立直觉 |

### 深一层：GLSL 报错怎么读

着色器编译错误只会出现在**控制台**，不会抛 JS 异常。页面就是一片黑或者材质变洋红。按这个顺序查：

| 报错关键词 | 含义 | 常见原因 |
| --- | --- | --- |
| `undeclared identifier` | 变量没声明 | uniform / varying 在两边少写了一份；或 `transformed` 用得太早 |
| `type mismatch` | 类型不匹配 | `float` 写成 `1` 而不是 `1.0`——GLSL 对整数/浮点极其严格 |
| `no matching overloaded function` | 函数参数类型不对 | `pow(负数, 0.5)`、`mix(vec3, vec3, int)` 这类 |
| `varying count exceeded` | varying 太多 | 移动端上限低，把不用的 varying 删掉 |
| `loop index cannot be compared` | 循环写法受限 | WebGL1 要求循环上界是常量；WebGL2 宽松很多 |

::: warning 一个价值十分钟的提醒
GLSL 里 `1` 是 `int`，`1.0` 才是 `float`。`sin(vUv.y * 10)` 会直接编译失败，必须写 `10.0`。

遇到黑屏先看控制台——**90% 的 shader 问题在编译阶段就已经报错了**，只是没弹出来你没看见。
:::

## 六、学习建议

::: warning 注意
着色器有一定门槛，别指望一天学会。建议路线：

1. 先改现成 shader 的参数，看效果变化
2. 理解 `uv`、`uniform`、`varying` 三个概念
3. 学会用 `sin/cos/mix/smoothstep` 做基本图形
4. 去 Shadertoy 网站看别人的作品和源码
:::
