# 加载外部模型

现实项目不可能全靠手搓立方体。真实模型通常用 Blender、Maya、Cinema4D 等软件做好，再导出成 3D 文件给网页用。

## 一、格式选择：GLTF 是王道

| 格式 | 说明 | 推荐度 |
|---|---|---|
| **GLTF / GLB** | 现代 Web 3D 标准，体积小、加载快、支持材质动画 | ⭐⭐⭐⭐⭐ |
| OBJ | 老格式，只有几何体，没有材质动画 | ⭐⭐ |
| FBX | 功能全但不是网页原生格式，需要先转换 | ⭐ |
| STL | 3D 打印用，只有几何 | ⭐ |

::: tip 大白话时间
**GLB 就是 3D 世界里的 JPG**——一个文件打包了模型、材质、贴图、动画，浏览器加载特别快。

GLTF 有两种形式：`.gltf`（文本 JSON + 外部贴图文件）和 `.glb`（二进制，全部打包成一个文件）。**日常用 GLB 最省事。**
:::

### 深一层：glTF 文件里到底装了什么

知道结构，排错时才知道问题出在哪一环。`.gltf` 本质是一个 JSON，`.glb` 是把这个 JSON 和所有二进制数据打包成一个文件：

```txt
glTF 文件
├── scenes          场景树（有几个场景、根节点是谁）
├── nodes           节点层级（父子关系、每个节点的位移旋转缩放）
├── meshes          几何体（顶点、索引、法线）
├── materials       材质（PBR 参数）
├── textures/images 贴图（.gltf 里是外部文件，.glb 里内嵌）
├── animations      动画片段（关键帧数据）
└── skins           骨骼蒙皮（人物、角色）
```

对应到 `GLTFLoader` 的返回值：

```js
const gltf = await loader.loadAsync('/model.glb');

gltf.scene;       // THREE.Group —— 场景树，直接 add 进场景的就是它
gltf.scenes;      // 所有场景（一般只用第一个）
gltf.animations;  // THREE.AnimationClip[] —— 动画片段
gltf.cameras;     // 模型里定义的相机（有时导入后直接用它）
gltf.parser;      // 高级用法：自己解析某个 glTF 扩展
```

::: tip 大白话时间
GLB 就像**一个行李箱**：模型、贴图、动画全塞在里面，拉链一拉走人。

`.gltf` 则是**一堆分开的行李**：JSON 是清单，`.bin` 是几何数据，贴图是另外几个文件。少带一件（比如贴图 404），模型就变成白色或黑色。
:::

**加载失败时按这个顺序看：**

| 现象 | 大概率原因 |
| --- | --- |
| 整个模型不出现，控制台 404 | 路径不对，或 `.gltf` 引用的外部贴图/`.bin` 丢了 |
| 模型是纯白/纯黑 | 贴图没加载，或者缺环境贴图（金属材质没反射源） |
| 模型有但特别大/特别小 | 导出软件单位不一致 → 用第 3 节的 `Box3` 自动归一化 |
| 模型透明/破面 | 导出时法线或双面设置不对，或缩放用了负值 |
| 动画不播 | 没建 `AnimationMixer`，或 `delta` 没传对 |

## 二、GLTFLoader 基本用法

```js
import { GLTFLoader } from 'three/addons/loaders/GLTFLoader.js';

const loader = new GLTFLoader();

loader.load(
  '/models/robot.glb',
  (gltf) => {
    const model = gltf.scene;
    scene.add(model);
  },
  (progress) => {
    // 加载进度
    console.log('已加载', (progress.loaded / progress.total * 100) + '%');
  },
  (error) => {
    console.error('模型加载失败：', error);
  }
);
```

### 深一层：用 Promise 写法，别让回调套娃

上面是 Three.js 最传统的回调写法，简单场景够用。但项目一大，模型、贴图、环境光要一起加载，回调一层套一层很快就乱了。r187 所有 Loader 都提供 `loadAsync()`，返回 Promise，可以直接 `async / await`：

```js
async function loadRobot(url) {
  const loader = new GLTFLoader();

  try {
    // 第二个参数依然是进度回调，用法和 load() 一致
    const gltf = await loader.loadAsync(url, (event) => {
      if (event.total) {
        console.log('加载进度', (event.loaded / event.total * 100).toFixed(0) + '%');
      }
    });
    scene.add(gltf.scene);
    return gltf;
  } catch (err) {
    console.error('模型加载失败：', err);
    // 返回一个兜底物体，别让整个页面白屏
    return createFallback();
  }
}

function createFallback() {
  const mesh = new THREE.Mesh(
    new THREE.BoxGeometry(1, 1, 1),
    new THREE.MeshStandardMaterial({ color: 0x888888, wireframe: true })
  );
  mesh.userData = { id: 'LOAD_FAILED', fallback: true };
  scene.add(mesh);
  return null;
}
```

一次性加载多个资源时，`Promise.all` 比嵌套回调清爽得多：

```js
import { GLTFLoader } from 'three/addons/loaders/GLTFLoader.js';
import { RGBELoader } from 'three/addons/loaders/RGBELoader.js';

const [robot, wood, env] = await Promise.all([
  new GLTFLoader().loadAsync('/models/robot.glb'),
  new THREE.TextureLoader().loadAsync('/textures/wood.jpg'),
  new RGBELoader().loadAsync('/hdr/studio.hdr')
]);

wood.colorSpace = THREE.SRGBColorSpace;  // 别忘了色彩管理（HDR 数据贴图不用设）
env.mapping = THREE.EquirectangularReflectionMapping;
scene.environment = env;
```

::: tip 大白话时间
回调写法像「点外卖时留个电话，到了给你打电话」；Promise 写法像「你在门口等着，等所有外卖都到了再一起开吃」。

后者写起来是**从上往下顺着读**的，出错了用 `try / catch` 一处兜住，不用每个回调里都写一遍错误处理。
:::

::: danger 三个高频坑
1. **加载失败一定要兜底。** 网络抖动、CDN 挂了、路径写错都是常事。不写 `catch`，模型区域就永远空着，用户还以为页面坏了。
2. **`loadAsync()` 不能取消。** 用户已经切走页面了，请求还在跑，回来后发现模型加到了新场景里。用 Vue3 时要在 `onUnmounted` 里加一个 `disposed` 标记，await 完先检查标记再 `scene.add()`。
3. **`onError` / `catch` 只告诉你失败，不告诉你为什么。** 大多数情况是：路径不对、跨域被拦、`.glb` 里引用的外部贴图 404。打开浏览器 Network 面板看具体哪个请求红了。
:::

## 三、调整模型大小与位置

不同软件导出的模型尺度千差万别（有的 0.01 单位大，有的 1000 单位大）。加载后通常需要调整：

```js
loader.load('/model.glb', (gltf) => {
  const model = gltf.scene;

  // 自动计算包围盒，缩放到合适大小
  const box = new THREE.Box3().setFromObject(model);
  const size = box.getSize(new THREE.Vector3());
  const center = box.getCenter(new THREE.Vector3());

  const maxDim = Math.max(size.x, size.y, size.z);
  const scale = 2 / maxDim;  // 让最大边变成 2 个单位
  model.scale.setScalar(scale);

  // 居中
  model.position.sub(center.multiplyScalar(scale));

  // 开启阴影
  model.traverse(child => {
    if (child.isMesh) {
      child.castShadow = true;
      child.receiveShadow = true;
    }
  });

  scene.add(model);
});
```

::: tip 大白话时间
这段代码在做一件很实用的事：**不管模型原本多大，都自动缩放到统一大小并居中。**

`Box3.setFromObject()` 会算出模型的「外接盒子」——能装下整个模型的最小长方体。拿到它的尺寸和中心点，就能算缩放比例、把模型挪到原点。

做产品展示时这段代码几乎是标配。
:::

## 四、播放模型自带动画

BLender 导出的 GLB 可以带动画（走路、开门等）：

```js
import { GLTFLoader } from 'three/addons/loaders/GLTFLoader.js';

let mixer, actions;

loader.load('/models/character.glb', (gltf) => {
  scene.add(gltf.scene);

  // AnimationMixer 是动画播放器
  mixer = new THREE.AnimationMixer(gltf.scene);

  // gltf.animations 是模型里所有的动画片段
  actions = {};
  gltf.animations.forEach(clip => {
    actions[clip.name] = mixer.clipAction(clip);
  });

  // 播放第一个动画
  actions[gltf.animations[0].name].play();
});

// 在动画循环里更新（别忘了 delta！）
const timer = new THREE.Timer();
renderer.setAnimationLoop(() => {
  timer.update();
  const delta = timer.getDelta();

  if (mixer) mixer.update(delta);

  renderer.render(scene, camera);
});
```

### 动画切换

```js
// 从走路切换到跑步，平滑过渡 0.5 秒
actions.walk.fadeOut(0.5);
actions.run.reset().setEffectiveWeight(1).fadeIn(0.5).play();
```

## 五、加载管理器（LoadingManager）

统一处理多个资源的加载状态：

```js
const manager = new THREE.LoadingManager();

manager.onStart = (url, loaded, total) => console.log('开始加载');
manager.onProgress = (url, loaded, total) => {
  console.log(`加载进度：${loaded}/${total}`);
  // 更新进度条 UI
};
manager.onLoad = () => console.log('全部加载完成！');
manager.onError = (url) => console.error('加载失败：' + url);

const gltfLoader = new GLTFLoader(manager);
const textureLoader = new THREE.TextureLoader(manager);

gltfLoader.load('/model.glb', ...);
textureLoader.load('/texture.jpg', ...);
```

::: tip 大白话时间
`LoadingManager` 就像个**收货总管**。你同时订了好几个包裹（模型、贴图），它帮你盯着：到货几个了、有没有丢件、什么时候全到齐。

做加载进度条、加载完成再开始动画，都靠它。
:::

## 六、DRACO 压缩模型

大型模型可以用 DRACO 压缩，体积能小 90%：

```js
import { GLTFLoader } from 'three/addons/loaders/GLTFLoader.js';
import { DRACOLoader } from 'three/addons/loaders/DRACOLoader.js';

const draco = new DRACOLoader();
draco.setDecoderPath('/draco/');  // 解码器文件，从 three/examples/jsm/libs/draco 复制
const loader = new GLTFLoader();
loader.setDRACOLoader(draco);

loader.load('/models/compressed.glb', (gltf) => scene.add(gltf.scene));
```

::: warning 注意
DRACO 需要在 Blender 导出时勾选压缩，并且要部署解码器文件。模型小的时候没必要折腾——压缩和解压本身也有成本。
:::

### 深一层：压缩方案怎么选

模型太大时别一股脑上 DRACO，先看瓶颈在哪：

| 瓶颈 | 表现 | 用什么 |
| --- | --- | --- |
| 几何体顶点太多 | `.glb` 大，但贴图不大 | **DRACO**（顶点压缩，体积小 90%） |
| 贴图太大 | 解包后纹理占几十 MB 显存 | **KTX2 / Basis**（GPU 直接读的压缩纹理） |
| 两者都大 | 工业模型、扫描模型常见 | DRACO + KTX2 一起上 |
| 模型不大，只是想少几个请求 | 几 MB 的展示模型 | 导出成 `.glb` 单文件就够了，别折腾 |

::: warning 压缩不是免费的
- DRACO 首次加载要下载解码器（约几百 KB）并解压，**小模型用了反而更慢**。
- KTX2 需要转码工具链（toktx / basisu），构建流程要改。
- 两种压缩都会让「模型加载完」的时间点变晚，进度条要如实反映。

经验值：**超过 5MB 的 GLB 才值得上 DRACO；贴图占比超过一半就先压贴图。**
:::
