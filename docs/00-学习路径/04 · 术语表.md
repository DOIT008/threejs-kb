# 术语表

Three.js 和 3D 图形学里有大量「黑话」。看文档时一个 `frustum`、一个 `PBR` 卡住，整段就看不懂了。这篇把高频术语按主题分组，给出**中英文对照 + 大白话解释**，遇到不懂的来搜一下就行。

::: tip 大白话时间
术语不是门槛，是**捷径**。一旦你知道 `draw call` 就是「CPU 给 GPU 下的一次画图命令」，看性能文章就顺了。别被英文吓到，很多词翻译过来特别朴素。
:::

## 一、场景、渲染与屏幕

| 英文术语 | 中文 | 大白话解释 |
|---|---|---|
| Scene | 场景 | 装所有 3D 物体的「大盒子」 |
| Camera | 相机 | 观众的眼睛，决定从哪看、看多远 |
| Renderer | 渲染器 | 把 3D 场景算成 2D 图片的「画师」 |
| WebGL | Web 图形库 | 浏览器里画画 3D 的底层接口，Three.js 建立在它之上 |
| WebGPU | Web GPU | 新一代浏览器图形接口，更快更强，r187 里已较成熟 |
| Canvas | 画布 | 网页上的 `<canvas>` 元素，3D 画面就画在这上面 |
| Viewport | 视口 | 画布上真正显示画面的那块矩形区域 |
| Frame | 帧 | 一张静止画面；每秒画很多张，连起来就是动画 |
| FPS | 每秒帧数 | 一秒画多少张，越高越流畅，60 是常见目标 |
| Frame rate | 帧率 | 同 FPS，画面更新的速度 |
| Frame time | 帧时间 | 画一帧花了多少毫秒，16.7ms ≈ 60 FPS |
| Draw call | 绘制调用 | CPU 给 GPU 下的「一次画图命令」；越多越卡 |
| Render pipeline | 渲染管线 | 从 3D 数据到屏幕像素的一整套流水线 |
| Rendering | 渲染 | 把 3D 数据算成 2D 图像的过程 |
| Rasterization | 光栅化 | 把三角形转换成屏幕上一个一个像素的过程 |
| Rasterizer | 光栅化器 | GPU 里负责光栅化的硬件单元 |
| Fragment | 片元 | 光栅化后「候选像素」，还没最终定颜色 |
| Pixel | 像素 | 屏幕上的最小颜色点 |
| Pass | 通道 / 处理遍 | 渲染的一个阶段，比如先画场景再做泛光 |
| Render target | 渲染目标 | 把画面画到「离屏画布」而不是直接上屏 |
| Framebuffer | 帧缓冲 | GPU 里暂存最终画面的内存区域 |
| G-buffer | 几何缓冲 | 延迟渲染里存位置/法线/颜色的几张纹理 |
| Depth buffer / Z-buffer | 深度缓冲 | 记录每个像素离相机多近，用来决定谁挡谁 |
| Stencil buffer | 模板缓冲 | 做遮罩、描边等效果的辅助缓冲 |
| Backface culling | 背面剔除 | 不画物体背对着相机的面，省性能 |
| Frustum | 视锥体 | 相机能看到的「金字塔形」空间范围 |
| Frustum culling | 视锥剔除 | 不在视锥里的物体直接不画，省性能 |
| Occlusion culling | 遮挡剔除 | 被别的物体完全挡住的不画（Three.js 需手动/扩展） |
| Clipping plane | 裁剪面 | 用一个平面把物体「切掉」一部分 |
| Near plane | 近裁剪面 | 相机最近能看到的距离，比这更近的不画 |
| Far plane | 远裁剪面 | 相机最远能看到的距离，比这更远的不画 |
| Antialiasing (AA) | 抗锯齿 | 消除边缘「锯齿感」的技术 |
| MSAA | 多重采样抗锯齿 | 一种常见的抗锯齿方法，质量好但有开销 |
| Tone mapping | 色调映射 | 把 HDR 的高亮度压缩到屏幕能显示的范围 |
| Color space | 颜色空间 | 颜色数值的解释方式，如 sRGB / Linear |
| sRGB | sRGB 色彩空间 | 网页和屏幕常用的色彩空间，颜色贴图要设成它 |
| Linear | 线性空间 | 光照计算用的空间，数值和亮度成正比 |
| Gamma | 伽马 | 亮度非线性校正，gamma 2.2 是常见约定 |
| HDR | 高动态范围 | 亮度可以超过 1.0，保留高光细节 |
| LDR | 低动态范围 | 亮度限制在 0~1 的普通图像 |
| Bloom | 泛光 | 亮的地方「溢出发光」的效果 |
| Post-processing | 后期处理 | 画面渲染完再加滤镜、发光、调色等 |
| Composer | 合成器 | 管理一系列后期处理通道的「流水线总管」 |
| Vignette | 暗角 | 画面四周变暗的效果 |
| Fog | 雾 | 远处物体逐渐融进背景色，营造距离感 |

## 二、几何体与网格

| 英文术语 | 中文 | 大白话解释 |
|---|---|---|
| Mesh | 网格 / 物体 | 几何体 + 材质组成的一个能显示的物体 |
| Geometry | 几何体 | 物体的「形状数据」：顶点、面、法线等 |
| BufferGeometry | 缓冲几何体 | r187 里标准的几何体形式，数据存在 GPU 缓冲里 |
| Vertex (pl. vertices) | 顶点 | 一个 3D 空间中的点，是构成形状的最小单位 |
| Vertex buffer | 顶点缓冲 | 存所有顶点数据的 GPU 内存块 |
| Index | 索引 | 复用顶点的编号，避免重复存同一个点 |
| Index buffer | 索引缓冲 | 存顶点索引的缓冲 |
| Face | 面 | 由若干顶点围成的多边形，通常是三角形 |
| Triangle | 三角形 | 3D 渲染的基本单位，所有模型最后都拆成三角形 |
| Polygon | 多边形 | 多条边围成的形状 |
| Edge | 边 | 两个顶点之间的线段 |
| Normal | 法线 | 垂直于表面的方向，决定光照怎么照 |
| Vertex normal | 顶点法线 | 每个顶点的法线，用来做平滑光照 |
| Tangent | 切线 | 表面上的方向向量，法线贴图要用 |
| UV / UV coordinates | UV 坐标 | 把 2D 图片「贴」到 3D 表面的坐标 (u 横, v 纵) |
| Attribute | 属性 | 顶点上携带的数据，如位置、法线、UV、颜色 |
| Primitive | 图元 | 最基本的绘制单元：点、线、三角形 |
| Topology | 拓扑结构 | 顶点怎么连成三角形的方式 |
| Wireframe | 线框 | 只画边不画面，能看到网格结构 |
| Triangulation | 三角剖分 | 把多边形拆成三角形的过程 |
| Tessellation | 细分 | 把面切得更细，让曲面更平滑 |
| Subdivision | 细分曲面 | 通过细分让低模变平滑的建模技术 |
| Bounding box (AABB) | 包围盒 | 包住物体的轴对齐长方体，做碰撞/剔除用 |
| Bounding sphere | 包围球 | 包住物体的球，做快速剔除用 |
| Convex hull | 凸包 | 包住所有点的最小凸形体 |
| LOD | 多细节层级 | 远处用低模、近处用高模，省性能 |
| Instancing | 实例化 | 一次绘制很多个相同物体，大幅省 draw call |
| InstancedMesh | 实例化网格 | Three.js 里做实例化的类 |
| Merge geometry | 合并几何体 | 把多个几何体合成一个，减少 draw call |
| Morph target | 形变目标 | 预设几个形状，在它们之间插值做动画（如表情） |
| Skinning | 蒙皮 | 让网格跟着骨骼动的技术 |
| Skeleton / Bone | 骨骼 / 骨头 | 角色动画的「骨架」结构 |
| Rigging | 绑定 | 给模型搭骨架并绑定权重的过程 |

## 三、材质、纹理与光照

| 英文术语 | 中文 | 大白话解释 |
|---|---|---|
| Material | 材质 | 物体表面的「外衣」，决定颜色、光泽、透明度 |
| Texture | 纹理 | 贴到物体上的图片 |
| Map | 贴图 | 纹理在材质里的具体用途，如 colorMap、normalMap |
| Albedo / Diffuse | 反照率 / 漫反射 | 物体本身的颜色（不含光影） |
| Specular | 高光 | 光滑表面反射出的亮斑 |
| Roughness | 粗糙度 | 表面有多粗糙：0 像镜子，1 像粉笔 |
| Metalness | 金属度 | 有多像金属：1 是金属，0 是非金属 |
| PBR | 基于物理的渲染 | 用物理规律模拟光照，结果更真实的渲染方式 |
| BRDF | 双向反射分布函数 | 描述光怎么从表面反射的数学函数 |
| BSDF | 双向散射分布函数 | BRDF 的推广，还包含透射/散射 |
| Fresnel | 菲涅尔效应 | 掠射角处反射更强的现象（水面边缘更亮） |
| IBL | 基于图像的照明 | 用环境贴图提供光照，比手打灯更真实 |
| Environment map | 环境贴图 | 记录周围环境的一张图，用来做反射和 IBL |
| Cube map | 立方体贴图 | 六张图拼成立方体，做天空盒/环境光照 |
| PMREM | 预过滤环境贴图 | 预处理的模糊环境贴图，PBR 环境光照要用 |
| Normal map | 法线贴图 | 用图片假装表面凹凸，不用真的加顶点 |
| Bump map | 凹凸贴图 | 用灰度图假装表面起伏，比法线贴图简单 |
| Displacement map | 位移贴图 | 真的移动顶点位置改变形状（开销大） |
| Height map | 高度图 | 用灰度表示高度的图，生成地形用 |
| AO / Ambient Occlusion | 环境光遮蔽 | 缝隙/角落变暗，增强立体感 |
| SSAO | 屏幕空间环境光遮蔽 | 在屏幕空间实时算的 AO 效果 |
| Emissive | 自发光 | 物体自己发光，不依赖灯光 |
| Alpha | Alpha 通道 | 图片里的透明度通道 |
| Opacity | 不透明度 | 0 全透明，1 完全不透明 |
| Transparency | 透明 | 让物体半透明，能看到后面的东西 |
| Blending | 混合 | 把新颜色和已有颜色按规则混合（透明物体用） |
| Depth test | 深度测试 | 比较深度决定这个像素要不要画 |
| Depth write | 深度写入 | 是否把当前深度写进深度缓冲 |
| Double side | 双面渲染 | 正反面都画，平面/单面模型需要 |
| Light | 光源 | 提供照明的物体 |
| Ambient light | 环境光 | 均匀照亮所有物体，没有方向、不投影 |
| Directional light | 平行光 | 像太阳，光线平行，能投影 |
| Point light | 点光源 | 像灯泡，向四面八方发光 |
| Spot light | 聚光灯 | 像手电筒，锥形范围 |
| Hemisphere light | 半球光 | 天空一个色、地面一个色，做自然光 |
| Shadow map | 阴影贴图 | 从光源视角渲染的深度图，用来判断阴影 |
| Shadow bias | 阴影偏移 | 微调阴影深度，消除「阴影痤疮」条纹 |
| Shader | 着色器 | 跑在 GPU 上的小程序，决定像素/顶点怎么算 |
| GLSL | OpenGL 着色语言 | 写 WebGL 着色器的语言 |
| Vertex shader | 顶点着色器 | 处理每个顶点位置的小程序 |
| Fragment shader | 片元着色器 | 处理每个像素颜色的小程序 |
| Uniform | 统一变量 | 从 JS 传给 shader 的全局参数，所有顶点/像素共享 |
| Varying |  varying 变量 | 顶点着色器传给片元着色器的插值数据 |
| ShaderMaterial | 着色器材质 | 让你自己写 GLSL 的材质 |
| Node material | 节点材质 | 用节点拼装着色器，替代手写 GLSL |
| TSL | Three.js 着色语言 | r187 主推的、用 JS 写节点材质的语言 |

## 六、常见材质与效果速查对照

最后这一小节把「名字看着像但容易混」的几组词放一起对比：

| 容易混的词 | 区别一句话 |
|---|---|
| Mesh / Geometry / Material | Mesh = Geometry（形状）+ Material（外衣），组装成能显示的物体 |
| Vertex / Fragment | Vertex 是顶点（每个角），Fragment 是候选像素（每个点） |
| Normal map / Bump map | Normal map 用 RGB 存方向更精确；Bump map 用灰度算高度更简单 |
| Roughness / Metalness | 粗糙度管「光滑还是磨砂」，金属度管「像不像金属」 |
| Perspective / Orthographic | 透视近大远小；正交尺寸恒定 |
| Euler / Quaternion | 欧拉角直观但会万向锁；四元数抽象但无锁、可平滑插值 |
| Opacity / Transparency | 透明度属性 vs 开启透明混合的开关，两个都要设 |
| Tone mapping / Color space | 色调映射压亮度范围；颜色空间解释颜色数值 |
| Frustum culling / Occlusion culling | 前者剔除「视野外」，后者剔除「被挡住」 |
| dispose / scene.clear() | clear 只是从场景移除引用；dispose 才真正释放 GPU 资源 |
