# 常见错误速查

写 Three.js 时，90% 的「玄学问题」其实就那么几十种。这篇文章把它们按「**错误信息 → 原因 → 修复**」整理成一张大表，出错时先来这里对号入座，能省下大量百度时间。

::: tip 大白话时间
排错就像医生看病：先**看症状**（报错信息 / 黑屏现象），再**查病因**（为什么），最后**开药方**（怎么改）。别一上来就乱改代码——先定位，再动手。
:::

## 一、高频错误总表

| # | 错误信息 / 现象 | 原因 | 修复步骤 |
|---|---|---|---|
| 1 | 控制台 `CORS policy: No 'Access-Control-Allow-Origin'` | 用 `file://` 直接打开 HTML，或跨域加载模型/纹理 | 用本地服务器（`npx vite` 或 `npx serve`）；确保资源服务器允许跨域；把模型放同源目录 |
| 2 | 整个页面黑屏，无报错 | 忘了 `document.body.appendChild(renderer.domElement)` | 创建渲染器后加上 `document.body.appendChild(renderer.domElement)` |
| 3 | 黑屏，但 canvas 在页面上 | 相机和物体重叠（都在原点）；或物体在相机背后 | 把相机往后移 `camera.position.z = 5`；或把物体挪到相机前方（负 z 方向） |
| 4 | 模型加载成功但「看不见」 | 模型尺寸太大/太小，或在视锥外 | 用 `Box3().setFromObject(model)` 看包围盒；居中缩放 `box.getCenter()`；调相机 `near/far` |
| 5 | 材质全黑（有灯还是黑） | 用了 `MeshBasicMaterial` 却期待受光；或法线反了；或没加灯 | 改用 `MeshStandardMaterial`；检查 geometry 法线；至少加一个 `AmbientLight` + `DirectionalLight` |
| 6 | 阴影边缘锯齿严重 | 阴影贴图分辨率低、视锥太大、类型不对 | `light.shadow.mapSize.set(2048, 2048)`；收紧 `shadow.camera` 范围；用 `THREE.PCFShadowMap` |
| 7 | 内存不停涨，页面越用越卡 | 切换场景时 geometry/material/texture 没 dispose | 见 [内存管理与泄漏排查](</09-生产级专题/01 · 内存管理与泄漏排查>)；用 `disposeScene()` 递归清理 |
| 8 | `Failed to resolve module specifier "three"` | 用了裸导入 `import ... from 'three'` 但没打包器/importmap | 用 Vite 搭建项目；或在 HTML 里加 importmap 指向 CDN 的 three.module.js |
| 9 | `Cannot find module 'three'` / `npm ERR` | 没装依赖或 cwd 不对 | 在项目根目录运行 `npm install three`；确认 `package.json` 里有 three |
| 10 | `WebGL context lost` | GPU 资源耗尽、驱动崩溃、切换标签页太久 | 监听 `webglcontextlost` 事件并 `preventDefault()`；减少纹理尺寸/数量；刷新页面 |
| 11 | 纹理上下颠倒 | 图片默认 flipY，与某些模型/坐标系不匹配 | `texture.flipY = false; texture.needsUpdate = true`；glTF 一般由加载器自动处理 |
| 12 | 纹理颜色发暗/发灰 | 颜色纹理没设 sRGB 色彩空间 | `texture.colorSpace = THREE.SRGBColorSpace`（法线/粗糙度贴图保持 `NoColorSpace`） |
| 13 | 改了相机参数没反应 | 忘了更新投影矩阵 | 改完 `fov/aspect/near/far` 后调用 `camera.updateProjectionMatrix()` |
| 14 | 窗口缩放后画面拉伸变形 | resize 时没同步相机和渲染器 | 监听 resize：`camera.aspect = w/h; camera.updateProjectionMatrix(); renderer.setSize(w, h)` |
| 15 | 物体背面看不见 | 材质默认只渲染正面 | `material.side = THREE.DoubleSide`（平面、单面模型常见） |
| 16 | 两个面重叠处闪烁（z-fighting） | 两个物体深度太接近 | 拉开一点距离；调 `polygonOffset`；减小 `near` 增大 `far` 精度 |
| 17 | 点击拾取没反应 | 射线检测对象列表不对，或坐标没归一化 | 用 `intersectObjects(scene.children, true)`；鼠标坐标要转成 -1~1 的 NDC；recursive 传 true |
| 18 | glTF 模型动画不动 | 创建了 mixer 但没在循环里 update | 循环里 `mixer.update(delta)`；用 `Timer` 或 `performance.now()` 算 delta |
| 19 | 阴影完全不出现 | 少了开关或相机范围没覆盖 | `renderer.shadowMap.enabled = true`；灯 `castShadow = true`；物体 `castShadow/receiveShadow = true`；调 `shadow.camera` |
| 20 | 半透明物体排序错乱、穿插 | 透明物体按距离排序，互相交叉时出错 | 调整 `renderOrder`；关闭 `depthWrite`；避免大面积透明物体互相嵌套 |
| 21 | 纹理模糊成马赛克 | 没开 mipmap 或过滤方式不对 | `texture.generateMipmaps = true`；`minFilter = LinearMipmapLinearFilter`；图片尺寸用 2 的幂 |
| 22 | 画面卡顿、掉帧严重 | draw call 太多 / 三角形太多 / 填充率爆了 | 见 [性能剖析与调优](</09-生产级专题/03 · 性能剖析与调优>)；用 InstancedMesh、LOD、合并几何体 |
| 23 | 导入 OrbitControls 报错 | addon 路径写错（r187 在 `three/addons/`） | `import { OrbitControls } from 'three/addons/controls/OrbitControls.js'` |
| 24 | 后期处理加了但画面全黑 | composer 尺寸没同步，或没用 composer.render | resize 时 `composer.setSize(w, h)`；循环里用 `composer.render()` 替代 `renderer.render()` |
| 25 | `THREE is not defined` | 用 script 标签引入但没用模块方式 | 用 `<script type="module">` + `import * as THREE from 'three'`；别混用全局 script |
| 26 | 部署后资源 404（本地正常） | Vite 打包路径不对（base 配置） | `vite.config.js` 设 `base: './'`（相对路径）；或用绝对路径部署到域名根 |
| 27 | 修改 geometry 数据后形状不变 | 改完顶点数据没通知 GPU | `geometry.attributes.position.needsUpdate = true`；需要时 `computeVertexNormals()` |
| 28 | 场景背景想透明却不透明 | renderer 默认不透明 | `new THREE.WebGLRenderer({ alpha: true })`；`renderer.setClearColor(0x000000, 0)` |
| 29 | 物体旋转有「万向锁」抖动 | 用欧拉角在特定角度丢失自由度 | 改用 `Quaternion`：`mesh.quaternion.setFromAxisAngle(...)` |
| 30 | 画面颜色偏暗/偏亮不对 | 色调映射 / 色彩空间配置不对 | `renderer.outputColorSpace = SRGBColorSpace`；`renderer.toneMapping = THREE.ACESFilmicToneMapping` |
| 31 | 动画速度忽快忽慢 | 用固定步长而不是按时间 | delta 用 `performance.now()` 时间差；不要每帧 `+= 0.01` |
| 32 | 页面切到后台再回来动画「跳一下」 | 后台暂停时积累了巨大 delta | 限制 delta 上限 `Math.min(delta, 0.1)` |
| 33 | 模型加载进度卡在 0% | 服务器没返回 Content-Length（gzip 常见） | 进度条改用已加载字节显示，或忽略百分比只显示「加载中」 |
| 34 | `Texture marked for update but no image data found` | 纹理加载还没完成就用了 | 在 `TextureLoader.load(url, onLoad)` 的回调里再用纹理 |
| 35 | 线段/点云显示成一坨 | 材质用错 | 线用 `LineBasicMaterial`，点用 `PointsMaterial`，别用 Mesh 材质 |
| 36 | `RangeError: Maximum call stack` 在 traverse 里 | 在遍历时又往场景里 add 物体 | 遍历前先收集到数组，遍历完再修改场景结构 |

## 二、重点错误详细修复

上面表格够快查，但有几个「明星问题」值得展开讲，照着做基本一次就好。

### 2.1 黑屏排查三步法

按顺序检查，90% 的黑屏都能定位：

```js
// ① canvas 加到页面了吗？
document.body.appendChild(renderer.domElement);

// ② 相机能看到物体吗？相机往后退，别贴脸
camera.position.set(0, 0, 5);
camera.lookAt(0, 0, 0);

// ③ 循环里真的在画吗？r187 推荐写法
renderer.setAnimationLoop(() => {
  renderer.render(scene, camera);
});
```

::: tip 大白话时间
黑屏就三件事：**画布没上墙、相机贴脸、没在画画**。按顺序排查，别一上来就怀疑是显卡坏了。
:::

### 2.2 材质全黑

```js
// 错误：用了不受光的材质，再怎么打灯都是黑（或纯色）
const bad = new THREE.MeshBasicMaterial({ color: 0x333333 });

// 正确：用 PBR 材质 + 加灯
const good = new THREE.MeshStandardMaterial({ color: 0x42b883, roughness: 0.4 });
scene.add(new THREE.AmbientLight(0xffffff, 1.5));
const dir = new THREE.DirectionalLight(0xffffff, 3);
dir.position.set(5, 10, 5);
scene.add(dir);
```

### 2.3 阴影出不来

```js
// 渲染器开阴影（r187 用 PCFShadowMap，别用废弃的 PCFSoftShadowMap）
renderer.shadowMap.enabled = true;
renderer.shadowMap.type = THREE.PCFShadowMap;

// 灯要能投影，并调整阴影相机范围
const light = new THREE.DirectionalLight(0xffffff, 3);
light.castShadow = true;
light.shadow.mapSize.set(2048, 2048);
light.shadow.camera.left = -10;
light.shadow.camera.right = 10;
light.shadow.camera.top = 10;
light.shadow.camera.bottom = -10;
scene.add(light);

// 物体：投射 + 接收
mesh.castShadow = true;
floor.receiveShadow = true;
```

### 2.4 模块导入失败（现代写法）

```html
<!-- 方式一：Vite 项目（推荐），直接裸导入 -->
<script type="module">
  import * as THREE from 'three';
  import { OrbitControls } from 'three/addons/controls/OrbitControls.js';
</script>
```

```html
<!-- 方式二：无构建工具，用 importmap -->
<script type="importmap">
{
  "imports": {
    "three": "https://cdn.jsdelivr.net/npm/three@0.187.0/build/three.module.js",
    "three/addons/": "https://cdn.jsdelivr.net/npm/three@0.187.0/examples/jsm/"
  }
}
</script>
<script type="module">
  import * as THREE from 'three';
</script>
```

### 2.5 纹理颜色发暗

```js
const tex = new THREE.TextureLoader().load('color.jpg');
tex.colorSpace = THREE.SRGBColorSpace; // 颜色贴图用这个

const normal = new THREE.TextureLoader().load('normal.jpg');
// 法线/粗糙度/金属度贴图保持默认 NoColorSpace，别设 sRGB
```

## 三、排错工具箱

| 工具 / 手段 | 干嘛用的 | 怎么用 |
|---|---|---|
| 浏览器控制台 | 看报错、看警告 | F12 → Console，红色必看 |
| `renderer.info` | 看 draw call、三角形数、纹理数 | 控制台打印 `renderer.info.render` |
| Chrome Memory 面板 | 抓内存泄漏 | Performance → Memory，拍快照对比 |
| Spector.js | 抓每一帧的 WebGL 调用 | 浏览器插件，录制一帧分析 |
| three.js devtools | 可视化看场景树、材质、几何体 | 浏览器插件 |
| `console.log(scene.children)` | 最朴素但有效 | 确认物体真的加进场景了 |

::: warning 注意
排错时**一次只改一个地方**，改完刷新看效果。同时改三四个地方，你永远不知道到底哪个起作用了——这是新手最容易踩的坑。
:::

::: tip 大白话时间
报错信息不是敌人，是**线索**。认真读那行红字，十次有八次它已经告诉你哪里错了。别看到红字就慌，复制下来搜一下，往往有现成答案。
:::
