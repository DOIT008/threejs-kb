# Vue3 + Three.js 集成说明

::: tip 大白话时间
把 Vue 想成餐厅里那个事无巨细的领班——谁来吃饭、点什么菜，都要登记在册；Three.js 像后厨那位认死理的老厨师，只认没被别人碰过的原装食材。领班要是顺手给食材套上一层保鲜膜（响应式代理），老厨师当场就撂挑子：这不是我认识的那块肉。
核心矛盾一句话：Vue 见啥都想"包一层管起来"，而 Three.js 的零件一旦被包就不认主、还占着显卡不放。
只要你打算用 Vue 搭界面、用 Three.js 画画面，这一册就是给你准备的。
:::

::: tip 这一册解决什么问题
前面 12 个案例是「纯 Three.js」——一个 HTML 文件搞定。但真实项目里，你多半会用 Vue3 搭界面：**控制面板、按钮、表单、路由全交给 Vue，3D 画面交给 Three.js**。这一册就讲这两位怎么搭伙干活，以及怎么才能不踩坑。
:::

## 先准备环境

需要一个 Vue3 项目（Vite 脚手架），Three.js 用 npm 安装：

```bash
npm create vue@latest my-three-app
cd my-three-app
npm install
npm install three
npm run dev
```

之后每个案例的代码，复制进 `src/components/xxx.vue` 就能用。案例里标了额外依赖的（Pinia、vue-router），按需 `npm install pinia` / `npm install vue-router`。

::: tip 为什么不用 CDN
前面纯 JS 案例能一个 HTML 跑通，是因为脚本直接引 CDN。Vue3 的真正威力在 **SFC 单文件组件**（`<template>` + `<script setup>` + `<style scoped>`），这需要 Vite 编译。既然都用 Vue3 了，建议直接建项目，别在 CDN 版里绕。
:::

## 三条铁律（踩坑预警）

::: warning 铁律 1：Three.js 对象绝不能塞进 reactive
Vue 的 `reactive()` 会把对象套一层 **Proxy 代理**。而 Three.js 内部大量用 `instanceof`、`===` 判断和闭包缓存，被代理后会**莫名其妙失效、内存暴涨、性能崩盘**。正确做法：用 `shallowRef()` 或 `markRaw()` 包住 Three.js 对象。这是 Vue3 + Three.js 的头号大坑，案例 09 专门讲。
:::

::: warning 铁律 2：onMounted 里初始化，onUnmounted 里清理
`ref` 指向的 `<div>` 要等组件挂载后 DOM 才存在，所以初始化必须放 `onMounted`。同理，组件销毁时**必须**停掉渲染循环、移除事件监听、`dispose()` 几何体/材质/渲染器——否则路由一切走，显存蹭蹭涨，页面越用越卡。
:::

::: tip 铁律 3：Vue 管 UI，Three.js 管画面，中间靠 watch 传话
别指望用 Vue 直接控制每一帧（响应式更新太慢，扛不住 60fps）。正确分工是：**Vue 的响应式变量只存「配置」**（颜色、速度、开关），用 `watch` 监听变化后去改 Three.js 对象；3D 那边的渲染循环独立跑。两条线各司其职，互不拖累。
:::
