# Vue3-08：路由切换与资源清理

::: tip 大白话时间
单页应用切路由，不是把整栋楼推倒重建，而是"退租换房"——组件被销毁，地还是那块地。退租时你要是没把前任的东西清走：灯还亮着（渲染循环空转）、水电还挂着（监听没摘）、大件家具还占着（显存没放），下家一进来就被坑，越切越卡。
核心一句：onMounted 里干过啥，onUnmounted 里就反着拆啥，一样都不能落下。
凡是路由里来回切 3D 页面的，这儿最容易翻车。
:::

::: tip 效果长啥样
两个页面 `/scene-a`、`/scene-b`，各有各的 3D 场景，点导航来回切。重点是：切换时旧场景被**彻底清理**——不会偷偷在后台继续渲染、不会内存泄漏、canvas 不会残留。这是 SPA 里 3D 应用最容易翻车的地方。
:::

## 为什么会泄漏

单页应用切路由时，组件会被**销毁**（不是刷新整个页面）。如果你没在 `onUnmounted` 里清理，就会留下：

| 没清理的东西 | 后果 |
|---|---|
| `setAnimationLoop` 循环 | 旧场景还在后台每帧渲染，越切越卡 |
| `resize` 等事件监听 | 监听器堆积，内存涨，且旧场景响应事件报错 |
| 几何体/材质/纹理 | **GPU 显存**不释放，切十几次显存爆掉 |
| canvas 元素 | 残留在 DOM 里，页面出现多个重叠画布 |

::: warning 核心区别
普通 DOM 组件销毁后，浏览器 GC 会自动回收内存。但 **GPU 显存不受 JS 垃圾回收管**——`dispose()` 是显式通知显卡「这块显存我不要了」。忘了它，GC 再努力也没用。
:::

::: tip 大白话时间
普通的 JS 内存，人一走浏览器 GC 会替你打扫；可 GPU 显存是显卡那边的地盘，JS 的清洁工根本进不去。`dispose()` 就是你亲自打电话给显卡："这块显存我不要了，回收吧。"不打这个电话，切十几次路由显存就爆了，页面卡成幻灯片。
:::

## 文件 1：路由配置 `src/router/index.js`

```js
import { createRouter, createWebHistory } from 'vue-router'

export default createRouter({
  history: createWebHistory(),
  routes: [
    { path: '/', redirect: '/scene-a' },
    { path: '/scene-a', component: () => import('../views/SceneA.vue') },
    { path: '/scene-b', component: () => import('../views/SceneB.vue') }
  ]
})
```

## 文件 2：`src/App.vue`（导航外壳）

```vue
<template>
  <nav>
    <router-link to="/scene-a">场景 A</router-link>
    <router-link to="/scene-b">场景 B</router-link>
  </nav>
  <!-- 关键：用 v-if 包裹，确保切路由时组件真的销毁重建 -->
  <router-view v-slot="{ Component }">
    <component :is="Component" />
  </router-view>
</template>
```

## 文件 3：`src/views/SceneA.vue`（场景页面）

```vue
<template>
  <div>
    <h2>场景 A：旋转立方体</h2>
    <div ref="container" class="canvas-box"></div>
  </div>
</template>

<script setup>
import { ref, shallowRef, onMounted, onUnmounted } from 'vue'
import * as THREE from 'three'

const container = ref(null)
const renderer = shallowRef(null)
let scene, camera, cube

onMounted(() => {
  const w = container.value.clientWidth, h = container.value.clientHeight
  scene = new THREE.Scene()
  scene.background = new THREE.Color(0x1a2a1a)
  camera = new THREE.PerspectiveCamera(60, w / h, 0.1, 100)
  camera.position.z = 4
  cube = new THREE.Mesh(
    new THREE.BoxGeometry(1.8, 1.8, 1.8),
    new THREE.MeshNormalMaterial()
  )
  scene.add(cube)

  renderer.value = new THREE.WebGLRenderer({ antialias: true })
  renderer.value.setSize(w, h)
  container.value.appendChild(renderer.value.domElement)
  renderer.value.setAnimationLoop(() => {
    cube.rotation.x += 0.01
    cube.rotation.y += 0.012
    renderer.value.render(scene, camera)
  })
  window.addEventListener('resize', onResize)
})

function onResize() {
  const w = container.value.clientWidth, h = container.value.clientHeight
  camera.aspect = w / h
  camera.updateProjectionMatrix()
  renderer.value.setSize(w, h)
}

// ⭐ 组件销毁时：反过来拆干净
onUnmounted(() => {
  console.log('场景 A 已清理')     // 切到 B 时看控制台验证
  renderer.value.setAnimationLoop(null)           // ① 停循环
  window.removeEventListener('resize', onResize)  // ② 摘监听
  scene.traverse(obj => {                          // ③ 释放 GPU 资源
    obj.geometry?.dispose()
    if (Array.isArray(obj.material)) obj.material.forEach(m => m.dispose())
    else obj.material?.dispose()
  })
  renderer.value.dispose()                         // ④ 释放渲染器
  renderer.value.domElement.remove()               // ⑤ 摘 canvas
})
</script>

<style scoped>
.canvas-box { width: 100%; height: 400px; }
.canvas-box :deep(canvas) { display: block; }
</style>
```

SceneB.vue 结构相同，只是场景颜色、物体不同，清理代码一模一样（可以用案例 04 的 composable 复用，彻底消除重复）。

## 关键点拆解

::: tip onUnmounted 是「退房时的检查清单」
住酒店退房要把钥匙交回、关灯、关空调——组件销毁也一样。写 `onUnmounted` 时，把它当成对照 `onMounted` 的**反向检查清单**：mounted 里 `addEventListener`，unmounted 里就 `removeEventListener`；mounted 里 `appendChild(canvas)`，unmounted 里就 `canvas.remove()`；mounted 里创建了几何体材质，unmounted 里就 `dispose()`。逐条对照，不会漏。
:::

::: tip 大白话时间
写 onUnmounted 别凭记忆，照着退房清单逐条核：mounted 里 addEventListener 的，这里就 remove；mounted 里 appendChild(canvas) 的，这里就 remove；mounted 里 new 出来的几何体材质，这里就 dispose。一条条对着划勾，保管不漏。
:::

::: warning keep-alive 是另一种情况
如果用了 `<keep-alive>` 包裹路由组件，组件**不会销毁**而是被缓存（`onDeactivated` 触发，`onUnmounted` 不触发）。这时不要把渲染循环停掉——回来时还要用。可以在 `onDeactivated` 里暂停渲染、`onActivated` 里恢复，用两个布尔标志控制。这和「彻底销毁」是两套逻辑，别搞混。
:::

::: tip 验证有没有泄漏
打开浏览器 DevTools → Performance Monitor，切路由十几次，观察 JS Heap Size 和 DOM Nodes。如果只涨不降，多半是哪里没清理干净。或者像示例那样在 `onUnmounted` 里 `console.log`，切走时看控制台有没有打印——没打印就等于清理代码没执行。
:::
