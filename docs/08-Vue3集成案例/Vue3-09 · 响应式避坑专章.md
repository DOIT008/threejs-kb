# Vue3-09：响应式避坑专章

::: tip 大白话时间
Vue 的响应式像个有洁癖的管家，见啥都要套一层保鲜膜（Proxy）登记在册；Three.js 像车间里认死理的老技工，只认没被包装过的原装零件。保鲜膜一套，老技工的卡尺、模具全失灵（`instanceof` 失效、性能暴跌），抽屉还越塞越满（内存涨）。
核心一句：Vue 的归 Vue，Three.js 的归 Three.js——响应式里只放颜色、数字这种"便签"，3D 对象一律用 shallowRef / markRaw 隔离起来。
当你撞见"代码明明没写错却出怪事"时，八成就是这儿出的岔子。
:::

::: tip 这一章为什么单独拎出来
Vue3 的响应式系统和 Three.js 的对象模型**天生有点不对付**。90% 的「Vue3 + Three.js 诡异 bug」都源于同一个原因：Three.js 对象被 Vue 的响应式代理包住了。这一章把坑挖开给你看，以后遇到类似现象能秒懂。
:::

## 坑 1：别把 Three.js 对象放进 reactive

::: warning 错误写法
```js
import { reactive } from 'vue'
const state = reactive({
  scene: new THREE.Scene(),     // ❌ 灾难开始
  cube: new THREE.Mesh(...)
})
```
:::

会发生什么？`reactive()` 会用 `Proxy` 递归代理对象的每一层。当你访问 `state.cube.position`，拿到的是一个 **Proxy 包装的 Vector3**，而不是原生的 `THREE.Vector3`。Three.js 内部大量用 `instanceof Vector3`、`obj.isMesh === true` 这类判断，代理后可能失效；而且每次访问都走代理拦截，性能大幅下降，内存也涨。

::: tip 正确写法一：shallowRef
```js
import { shallowRef } from 'vue'
const cube = shallowRef(new THREE.Mesh(...))
// 访问 cube.value 拿到的是原始对象，不被代理
cube.value.position.x = 1     // 直接改，没问题
```
`shallowRef` 只代理「`.value` 这个外壳」，不深入对象内部。你需要「整个替换」时（`cube.value = 新对象`）Vue 能感知；改内部属性不需要 Vue 感知（3D 渲染本来就不靠 Vue），正合适。
:::

::: tip 正确写法二：markRaw
```js
import { reactive, markRaw } from 'vue'
const state = reactive({
  name: '我的场景',
  cube: markRaw(new THREE.Mesh(...))   // ✅ 打上「别代理我」的标记
})
```
`markRaw()` 给对象盖个章，Vue 看到就跳过代理。适合你想把 3D 对象和普通状态放在一起管理的情况。
:::

::: tip 大白话时间
俩方法都是给 3D 物体发"免检证"，但发证方式不一样：`shallowRef` 是把物体单独装进一个"只认整盒替换"的盒子，里面装啥 Vue 一概不碰；`markRaw` 是给物体身上盖个"已认证、别碰我"的章，这样就能把它跟普通数据混在一个 reactive 里管。一个图省事单独放，一个图合群混着放。
:::

## 坑 2：从 reactive 里取出的对象是代理

::: warning 隐蔽的坑
```js
const state = reactive({ camera: markRaw(new THREE.PerspectiveCamera()) })
function foo() {
  const cam = state.camera   // 如果没 markRaw，这里拿到的是 Proxy
  cam.position.set(0, 0, 5)  // 可能行为异常
}
```
即使你小心翼翼，只要中间有一层忘了 `markRaw`，取出来的就可能是代理对象。用 `toRaw()` 可以拿到原始对象救急：
```js
import { toRaw } from 'vue'
const rawCam = toRaw(state.camera)   // 剥掉代理外壳，拿回原生对象
```
但**根本解法还是一开始就 markRaw/shallowRef**，别事后补救。
:::

::: tip 大白话时间
`toRaw` 像撕保鲜膜——东西已经被包上了，临时撕开救个急能用。但与其每次用之前都撕一遍，不如一开始就直接 markRaw 不让它包。记住：toRaw 是创可贴，shallowRef / markRaw 才是防患于未然。
:::

## 坑 3：数组里的 3D 对象

::: tip 场景里经常有个物体数组
```js
// ❌ 错误
const meshes = reactive([])
meshes.push(new THREE.Mesh(...))   // 放进去就被代理了

// ✅ 正确：用 shallowRef 包数组
const meshes = shallowRef([])
meshes.value.push(new THREE.Mesh(...))   // 数组里的对象不被代理
```
注意：用 `shallowRef` 包数组后，往里 `push` 不会触发 Vue 更新（浅层响应式只跟踪 `.value` 替换）。但对 3D 物体来说这恰恰是我们要的——渲染循环每帧自己读数组，不需要 Vue 帮忙更新界面。如果确实需要界面响应，改完手动 `triggerRef(meshes)`。
:::

## 坑 4：computed 里返回 3D 对象的属性

::: warning 看似无害
```js
const position = computed(() => cube.value.position)  // ❌
```
`computed` 会对返回值做响应式包装，把 `Vector3` 又套了一层。如果只是想在模板里显示坐标，返回**普通数值**而不是对象：
```js
const posX = computed(() => cube.value?.position.x.toFixed(2) ?? '0')
```
这样模板里 `{{ posX }}` 显示的是字符串，和 Three.js 对象完全解耦。
:::

## 诊断清单

遇到「明明写对了却出怪事」，按这个顺序排查：

| 症状 | 大概率原因 |
|---|---|
| `instanceof` 判断失败、`.isMesh` 失效 | 对象被代理了，用 `toRaw()` 验证 |
| 改了属性画面不动 | 改的是 Proxy 副本 / 忘了 `.value` / 忘了 `needsUpdate` |
| 性能突然很差、内存涨 | 深层响应式代理开销，检查是否用了 `reactive` 装 3D 对象 |
| 控制台报循环引用 / Maximum call stack | 响应式追踪到 Three.js 内部相互引用的对象图 |
| 模板里显示 `[object Object]` | 想显示 3D 对象本身，应该显示它的某个数值属性 |

::: tip 一句话总结
**Vue 的归 Vue，Three.js 的归 Three.js。** 响应式系统里只放「数据配置」（颜色字符串、数字、布尔、普通 JSON），Three.js 对象一律 `shallowRef` / `markRaw` 隔离。两边通过 `watch`（Vue→3D）和事件/回调（3D→Vue）通信，互不越界。遵守这条，上面所有坑都不会踩到。
:::
