# 粒子系统实验室

星空、烟花、沙尘、萤火虫——成千上万个"点"同时运动，靠的就是粒子系统。这个实验室让你调参数，看同一套机制怎么变出不同效果。

<ParticleLab />

## 粒子的本质

::: tip 大白话时间
一个粒子就是一个**顶点**。几千个粒子 = 几千个顶点，一次性交给显卡画，比你创建几千个 Mesh 快几百倍。

做法是：用 `BufferGeometry` 存一个位置数组（每个粒子三个数 x/y/z），用 `PointsMaterial` 规定每个点画成多大、什么颜色。想让粒子动，就在每帧改数组里的数，然后告诉 Three.js「数据变了，重新上传到显卡」（`needsUpdate = true`）。

这就是性能和灵活性的平衡点：数据在 CPU 改，渲染交给 GPU 批量做。
:::

## 三种运动模式

- **星系**：每个粒子绕中心转，转速和半径相关（内快外慢，像真实星系）。改粒子数看密度，改大小看亮度。
- **喷泉**：粒子不断向上喷，到顶后重置到底部。`place(i)` 负责重置——这是粒子系统的常见套路：**粒子池**，不销毁重建，只重置属性。
- **球壳**：粒子分布在一个球面上整体旋转。改颜色很适合做能量护盾、魔法球。

## 关键参数

| 参数 | 作用 | 调大会怎样 |
|---|---|---|
| 粒子数 | 顶点数量 | 更密集，但每帧计算量和上传量线性增加 |
| 点大小 | `PointsMaterial.size` | 更亮更糊，超过一定值会变成大方块 |
| `sizeAttenuation` | 是否随距离缩小 | 默认 true（近大远小），false 则所有点一样大 |
| `AdditiveBlending` | 叠加混合 | 粒子重叠处更亮，做发光效果必备 |
| `depthWrite: false` | 不写深度 | 避免半透明粒子互相遮挡出黑边 |

::: warning 性能红线
实验室里粒子数能拉到 2 万。但每帧改 2 万个顶点意味着 6 万个浮点数和一次 GPU 上传——低端设备会卡。真实项目里几十万粒子要用 **GPU 粒子**（在着色器里算运动，CPU 完全不参与），那是进阶话题了。
:::
