# 坐标、旋转、缩放

物体造出来之后，怎么摆放、转动、改变大小？靠三个属性：**position（位置）、rotation（旋转）、scale（缩放）**。

::: tip 大白话时间
把物体想象成一件家具：

- **position** = 把它搬到房间的哪个角落
- **rotation** = 把它转个方向（朝东还是朝西）
- **scale** = 把它拉大或压扁

这三个属性每个物体都有，改完立刻生效，不用重新创建。
:::

## 一、坐标系

Three.js 用**右手坐标系**：

| 轴 | 方向 | 大白话 | 颜色约定 |
|---|---|---|---|
| **X** | 左右 | 往右是正，往左是负 | 红 |
| **Y** | 上下 | 往上是正，往下是负 | 绿 |
| **Z** | 前后 | **朝你**是正，往屏幕里是负 | 蓝 |

::: tip 大白话时间
伸出右手：食指指向 X（右），中指指向 Y（上），大拇指指向 Z（朝自己）。这就是「右手坐标系」。

记不住也没关系，只要记住一个画面：**站在原点，X 往右走，Y 往天花板走，Z 往你脸上走。**

相机默认在 Z 轴正方向（比如 `z=5`）往原点看。所以「屏幕外面」就是 Z 的正方向。
:::

### 单位是啥？

**没有固定单位。** 你可以当它是米，也可以当它是厘米，全看你自己怎么设定。

::: tip 建议
统一当成「米」来想：人高 1.8，桌子高 0.75，房间高 3。这样调相机距离、光照范围时心里有数，不会乱。
:::

## 二、position：位置

```js
mesh.position.set(2, 1, -3);  // 一次性设置 x/y/z
mesh.position.x = 5;          // 单独改 x
mesh.position.y += 0.1;       // 在原来基础上加
mesh.position.z -= 1;
```

也可以单独用向量对象：

```js
mesh.position = new THREE.Vector3(1, 2, 3);
```

## 三、rotation：旋转

::: warning 注意
**单位是弧度（radian），不是角度（degree）！** `rotation.y = 90` 不是转 90 度，而是转 90 弧度（相当于转了 14 圈多）。
:::

```js
mesh.rotation.set(0, Math.PI / 2, 0); // 绕 Y 轴转 90 度
mesh.rotation.x = Math.PI;            // 绕 X 轴转 180 度
mesh.rotation.z += 0.01;              // 每帧绕 Z 轴转一点
```

换算关系：

| 角度 | 弧度 |
|---|---|
| 90° | `Math.PI / 2` |
| 180° | `Math.PI` |
| 360° | `Math.PI * 2` |
| 1° | `Math.PI / 180` |

嫌换算麻烦，写个小工具函数：

```js
const deg = d => d * Math.PI / 180;
mesh.rotation.y = deg(45); // 终于能写 45 度了
```

::: tip 大白话时间
一圈是 360 度 = `2π` 弧度，所以 π 弧度 = 180 度。

为什么程序员喜欢用弧度？因为它是数学里的「自然单位」，做 sin/cos 计算时不用额外转换。记住 `Math.PI` 就是半圈，基本够用了。
:::

### rotation.order：旋转顺序

```js
mesh.rotation.order = 'YXZ'; // 默认 XYZ
```

::: tip 大白话时间
先转 X 再转 Y，和先转 Y 再转 X，结果**不一样**！就像你把一本书先左右翻再上下翻，和反过来操作，最后朝向不同。

做第一人称相机时常用 `'YXZ'`（先左右看，再抬头低头），这样手感更自然。
:::

## 四、scale：缩放

```js
mesh.scale.set(2, 2, 2); // 整体放大 2 倍
mesh.scale.x = 0.5;      // 只在 X 方向压扁一半
mesh.scale.setScalar(3); // 三个方向一起放大 3 倍
```

::: warning 注意
- `scale` 设成 0 会让物体消失（法线算不出来，光照会出问题）
- 设成负值会翻面（有时候故意用来做镜像）
- 非等比缩放（比如 `scale.set(2,1,1)`）会让法线变形，Three.js 会自动处理，但极端比例下光照可能不对
:::

### 深一层：变换的三个高频坑

**坑 1：把角度当弧度传**

`rotation.y = 90` 看着像「转 90 度」，实际是 90 弧度 ≈ 14 圈。数字看着对，画面却转到不知哪去了。

```js
// 记不住就永远用工具函数
const deg = d => d * Math.PI / 180;
mesh.rotation.y = deg(90);
```

**坑 2：旋转顺序导致结果不一致**

欧拉角（rotation）是「按 X→Y→Z 依次转」，换个顺序结果就不同。最典型的是第一人称相机：默认 `XYZ` 顺序下，抬头再左右转会歪。

```js
camera.rotation.order = 'YXZ'; // 第一人称标配：先左右，再俯仰
```

::: tip 怎么判断该不该改顺序？
- 物体只是简单摆放 → 默认 `XYZ` 不用管
- 第一人称相机 / 万向节死锁 → 换 `YXZ`
- 从 Blender / 其他软件导入的动画 → **别改**，导出时的顺序要和运行时一致，否则动画会扭
:::

**坑 3：负缩放导致翻面**

`scale.x = -1` 做镜像很方便，但三角形绕序会反转，配合背面剔除会出现「模型从某个角度看是空的」。

```js
// 需要镜像时的稳妥做法
const mirrored = original.clone();
mirrored.scale.x = -1;
mirrored.material = original.material.clone();
mirrored.material.side = THREE.DoubleSide; // 两面都画，避免被剔除掉
```

`scale = 0` 更危险：法线矩阵不可逆，光照会算出 NaN，物体可能整个变黑或者闪烁。要隐藏物体用 `visible = false`，别用 `scale = 0`。

## 五、父子关系与 Group

物体可以有父子关系，形成一棵**场景树**：

```js
const group = new THREE.Group();
group.position.set(3, 0, 0); // 整组往右挪 3

const a = new THREE.Mesh(...);
a.position.set(1, 0, 0);     // 在组内的「相对位置」
group.add(a);

scene.add(group);
// a 的世界坐标是 (4, 0, 0)
```

::: tip 大白话时间
`Group` 就是个**纸箱**。你在箱子里摆好东西，然后搬箱子就行——箱子里的东西相对位置不变。

做一辆由几十个零件组成的车时特别好用：把零件都放进 `carGroup`，然后移动/旋转整个组，车就整体动了。轮子想单独转？直接转 `wheel.rotation` 即可。
:::

### 局部坐标 vs 世界坐标

```js
mesh.position;              // 局部坐标（相对父级）
mesh.getWorldPosition(v);   // 世界坐标（相对场景原点）
```

## 六、四元数 Quaternion（了解即可）

`rotation` 用三个角度表示旋转，有个著名问题叫**万向节死锁**（gimbal lock）——某些角度下会丢失一个旋转自由度。

四元数用四个数表示旋转，没这个问题，还能平滑插值（做旋转动画很丝滑）。

同一个旋转，`rotation` 和 `quaternion` 是两种表示，改一个另一个会自动同步：

```js
mesh.rotation.y = Math.PI / 2;
console.log(mesh.quaternion); // 已经跟着变了，不用手动转
```

### 深一层：gimbal lock 到底怎么破

::: tip 大白话时间
**万向节死锁不是「锁住不能转」，而是「两个轴重合了，少了一个方向」。**

想象一个陀螺仪：外圈、中圈、内圈三层框架。当中圈转到 90°，外圈和内圈就变成平行——这时候你转外圈还是转内圈，效果一样，本来三个自由度变成了两个。

`rotation` 是三个欧拉角（绕 X/Y/Z 各转多少），本质上就是这三层框架，所以会踩这个坑。
:::

**什么时候会真的遇到？**

做第一人称相机时最典型：角色抬头到接近 90°（直视天花板），再左右转，画面会诡异地翻滚。这就是 gimbal lock。

**两个解决方向：**

```js
// 方案 A：换旋转顺序为 YXZ（先左右看，再抬头低头），第一人称标配
camera.rotation.order = 'YXZ';
// 之后用 camera.rotation.y 控制左右、camera.rotation.x 控制俯仰
camera.rotation.y += mouseDeltaX * 0.002;
camera.rotation.x = Math.max(-Math.PI / 2 + 0.01,
  Math.min(Math.PI / 2 - 0.01, camera.rotation.x - mouseDeltaY * 0.002));
```

方案 A 里的 `±π/2` 附近留的 `0.01` 是**故意的余量**——永远不让俯仰角正好到 90°，从根上绕开死锁。这是最实用的做法。

```js
// 方案 B：全程用四元数，适合「从朝向 A 平滑转到朝向 B」
const q1 = new THREE.Quaternion().setFromEuler(new THREE.Euler(0, 0, 0));
const q2 = new THREE.Quaternion().setFromEuler(new THREE.Euler(0, Math.PI, 0));

const start = performance.now();
renderer.setAnimationLoop(() => {
  const t = Math.min((performance.now() - start) / 1000, 1); // 0 → 1

  // slerp = 球面线性插值：沿最短弧匀速转，不会走「穿模」的直线
  mesh.quaternion.slerpQuaternions(q1, q2, t);

  renderer.render(scene, camera);
});
```

::: danger 四元数最常见的两个错
1. **直接 `lerp` 不用 `slerp`。** 四元数 `lerp` 是直线插值，中间状态的四元数不再是单位长度，旋转会出现加速/减速甚至扭曲。要用 `slerp`（球面插值）。
2. **混用 `rotation` 和 `quaternion`。** 它们是同一个旋转的两种表示，改一个另一个会跟着变。但在一段动画里来回改，很容易互相覆盖。选一种用到底。

**好消息：** 你不需要手动 `normalize()`。Three.js 的 `slerpQuaternions()` 内部会处理。
:::

::: tip 小贴士
日常开发用 `rotation` 就够了。只有当你需要做「在两个朝向之间平滑过渡」（比如角色转身、相机绕物体飞）、或者俯仰角可能接近 ±90° 时，才需要切换到四元数 / `YXZ` 顺序。
:::

## 七、lookAt：自动对准

```js
mesh.lookAt(0, 0, 0);       // 看向原点
mesh.lookAt(camera.position); // 一直看着相机（做公告板/精灵）
```

::: tip 大白话时间
`lookAt` 帮你算好旋转角度，命令物体「盯着那个点看」。

相机要看向目标用 `camera.lookAt(...)`；物体要面向某个方向用 `mesh.lookAt(...)`。注意物体的「正面」默认是 **+Z 方向**——如果你做了个箭头模型，箭头得朝 +Z 摆，lookAt 才对。
:::
